> 基于 `src/` 全量代码阅读整理。版本：0.0.0 · 技术栈：Vue 3 + TypeScript + Vite + Pinia + 原生 CSS。

## 1. 项目定位

业务需求协作平台前端，覆盖需求从「创建 → BRD 撰写 → 派发 → 承接 → PRD 拆解 → 业务审核 → 完成」的全生命周期，并以 AI Agent 会话驱动流程推进。由 6 月 24 日演示版迁移而来，已接入内网业务后端（`/apbm`）与中心化 Harness 网关（`/api/harness`）。

### 1.1 核心用户角色

- **业务经理**（如王大陆）：发起需求、撰写 BRD、提交审核、通过/退回 PRD
- **产品经理**（如李一飞等）：承接任务、编写 PRD、提交业务审核
- **AI Agent 团队**：群聊负责人 / 需求澄清助手 / BRD 草拟助手 / 派发建议助手（见 `constants/index.ts:AGENT_STEPS`）

### 1.2 功能模块总览

#### 页面路由一览

|------|----------|---------|-----------|

#### 各模块详细说明

**1. 首页（HomePage）**

- **定位**：登录后默认落地页，承担「快速创建需求」和「待办/最近事项入口」两个职责
- **输入区**：textarea 自适应高度（70~200px）+ 工作空间选择器（必选）+ 附件上传（最多 5 个/单文件 8MB）
- **列表区**：待办事项（后端待办中心接口，pageSize=50，滚动加载更多每页 4 条）/ 最近事项（按 workspaceName 分组 pills 筛选）
- **创建流程**：校验文字非空 + 空间已选 → `createBusinessDemand` → 阶段 Loading（workspace→session→attachments）→ 自动跳转工作区
- **特殊处理**：401/403 触发 Electron 登出；附件失败提供「重试/移除/不带附件发送」三选项

**2. 工作台（PoolPage）**

- **定位**：泳道看板视图，一目了然展示所有需求与任务的流转位置
- **五泳道**：业务需求 → 需求待承接 → 产品拆解 → 业务审核中 → 已完成（可勾选隐藏）
- **卡片类型**：业务卡（需求标题 + 子任务 chips + 退回标记）/ 任务卡（标题 + 领域 tag + 关联需求 + 负责人 + 时间前缀）
- **筛选**：关键词实时过滤 + 领域下拉 + 是否显示已完成
- **交互**：hover 同组高亮；点击卡片进入对应会话；空状态区分「有筛选清空」/「无数据去创建」

**3. 会话工作区（WorkspacePage）**

- **定位**：系统核心工作页面，承载 AI 对话与协作文档的完整交互
- **布局**：CSS Grid 双栏（Chat 2fr : Doc 3fr），中间 6px 可拖拽 splitter（ratio 0.28~0.72 持久化）
- **响应式**：≤1180px doc 列最小 320px；≤900px 强制单栏（narrow 模式 Chat/Doc 互斥全屏）
- **ChatPanel**：虚拟滚动消息时间线 + 工具卡（承接/派发/系统选择/转派）+ QuestionDock + PermissionDock + Composer（@mention + 附件 + 停止生成）
- **DocPanel**：Tiptap + Yjs 协同编辑 + BRD/PRD 双模式 + 大纲导航 + 批注/变更历史侧栏 + Ctrl+F 文档内查找 + 下载(docx/md)
- **BRD 修改稿**：范围校验 → 独立 roomId 草稿编辑 → 发布（fast publish / Yjs 同步后 complete）→ reopen
- **引用/审核导航**：AI 提问卡章节引用 → 文档定位（12s 超时）→ 多候选消歧 → 返回恢复选区
- **Delivery 轮询**：产品会话 running 1.2s / 其他 5s；SSE 事件即时刷新；review 状态自动打开审核清单

**4. 资产模块（AssetSearchPage / AssetDetailPage / AssetDomainDetailPage）**

- **检索 Tab**：Enter 触发搜索（batch=20 分页）+ 无限滚动（距底 140px）+ 热搜 TOP 榜（接口失败回退默认 10 条）+ 点击结果先上报再跳详情
- **矩阵 Tab**：L0 价值链行 → L1 领域 chips → 展开系统列表 → 点击系统下钻到领域明细页
- **领域明细页**：面包屑导航 + 侧栏主题树（带数量）+ 模糊搜索（id/code/name/desc）+ 功能表格（查看详情跳资产详情）
- **资产详情页**：三 Tab（详细信息/标签信息/血缘信息）
  - 详情：FDD 按 5 模块渲染（业务流程/业务规则表格/UI/业务对象/非功能）；BRD/PRD Markdown→HTML + 目录锚点
  - 标签：L1 价值链 → L2 领域 → L3 主题活动时间线 + 同标签资产分组（BRD/PRD/FDD）
  - 血缘：BRD→PRD→FDD 三层图 + 关键词搜索高亮 + 缩放(0.5~2.0) + 点击节点跳转
- **数据策略**：按 assetId 缓存，切资产时 reset + 重新加载；异步完成后校验 id 防竞态

**5. 应用拆解（AppDecomposePage）**

- **定位**：产品拆解阶段，将业务功能拆分为前后端应用节点并确认同步
- **左栏**：PRD 列表（进行中/已同步 Tab + 仅看自己 + 关键字搜索防抖 400ms）+ PrdCard 可展开模块
- **右栏**：选中模块的功能点列表（FeatureCard），每个功能含应用节点行（行内编辑/添加/删除/修改）
- **AI 拆解**：启动 Harness 会话 → 1s 轮询状态 → 30min 超时 abort；sessionStorage 跨页保持进行中任务
- **操作**：确认（batchSave syncStatus=1）/ 取消确认（本地覆盖）/ 同步（dismantled syncStatus=2，需二次确认）/ 全部确认 / 全部取消
- **弹窗**：添加节点（subsysQueryFromMCP 多选）/ 修改节点（单选替换）/ 转派（人员搜索防抖 300ms + 理由 maxlength=200）/ 重新拆解（补充原因 textarea rows=5）
- **权限**：仅 decomposer 本人或未分配时可操作

**6. 登录（LoginPage / SsoLogin）**

- **账号密码**：居中卡片表单，用户名 datalist 提供演示用户候选，Enter 提交，请求中按钮 disabled
- **SSO Token**：全屏 loading spinner，watch route.query.token → performTglogin（支持 hash change 不重挂载场景）
- **旧路径兼容**：Nginx rewrite `/tglogin*` → index.html → 前端 legacyTgloginUrl 转为 hash URL

## 3. 路由与导航设计

### 3.1 路由表（`router/index.ts`）

```
/login                    → LoginPage（懒加载）
/tglogin                  → SsoLogin（懒加载）
/                         → AppShell（布局壳）
  /home                   → HomePage
  /pool                   → PoolPage
  /workspace              → WorkspacePage
  /asset-search           → AssetSearchPage
  /asset-matrix           → AssetSearchPage（同一组件，Tab 不同）
  /asset-detail           → AssetDetailPage
  /asset-domain-detail    → AssetDomainDetailPage
  /app-decompose          → AppDecomposePage
/:pathMatch(.*)*          → redirect /home
```

所有页面均使用 `() => import(...)` 懒加载。

### 3.2 导航守卫（`connectAppRouter`）

1. **认证守卫**：未登录访问非 login/tglogin 页面 → 强制跳转 `/login`
2. **资源存在性守卫**：`asset-detail` 需 `store.activeAssetItem`、`asset-domain-detail` 需 `store.activeDomainDetail`，否则回退 `asset-search`
3. **工作区进入准备**：首次进入 `workspace` 时先设 `conversationEntering=true` + 切壳层，再 `await ensureWorkspaceSessionList({refresh:true})` 加载会话列表
4. **afterEach 同步**：`store.page = to.name`（唯一 route→store 写入点）；`asset-search/matrix` 同步 `assetViewTab`；外部进入 `pool` 时 `enterWorkbench()`；进入 `home` 且已登录时 `restoreAuthRecovery()`
5. **登出监听**：`watch(store.isAuthenticated)` → 未登录且不在 tglogin → `replace('/login')`

### 3.3 Store ↔ Router 解耦

`navigation.ts` 提供 `bindPageNavigation` / `navigateToPage`，store 中 `setPage()` 通过 WeakMap 查找当前绑定的 navigate 函数，避免循环依赖。

## 4. 状态管理设计

### 4.1 主 Store（`stores/app.ts`）

采用 Pinia Options API（`defineStore('app', { state, getters, actions })`），单例承载全部业务状态。

#### State 分组

| 分组 | 关键字段 |
|---|---|
| 页面/布局 | `page`、`previousPage`、`railCollapsed`、`workspaceViewport`、`chatFullscreen`、`docMinimized` 等 |
| 认证 | `currentUserId`、`currentUserSsoNo`、`loginUsername`、`isAuthenticated`、`authRecoveryRestoring` |
| 空间（工作空间） | `spaces`、`selectedSpaceId`、`spaceAssignments`、`collapsedSpaces`、`projects`、`activeProjectId` |
| 需求与会话 | `requirements`、`conversations`、`activeConversationId`、`activeConversationCardKey`、`activeDocMode` |
| 泳道看板 | `poolBoard: { business: PoolBizCard[], tasks: PoolTaskCard[] }`、`poolKeyword`、`poolShowCompleted` |
| 资产 | `assetResults`、`assetValueChains`、`assetTopicsByDomain`、`assetFunctionsByTopic`、`assetDetailId` 等 |
| 文档 | `docContents`、`docOutlines`、`documentLoading/Saving/Downloading` |
| 会话同步过渡态 | `conversationEntering`、`conversationSyncPending/Error`、`taskAccepting`、`conversationEntryRequestId` |
| 待办/最近 | `homeTodoRequirements`、`homeRecentRequirements`、`homeTodoPageNo/HasMore` |
| 草稿/附件 | `draft`、`draftByConversation`、`draftAttachments`、`homePrompt`、`homeAttachments` |
| 派发/审核 | `prdRevisionPhase`、`technicalBreakdownOffer`、`pendingTaskAcceptanceNavigation` |
| 子智能体 | `subagentDetailSessionId/ParentId/Title/Loading/Error` |
| 用户上下文版本 | `userContextVersion`（每次切换用户 +1，用于丢弃过期异步结果） |

#### 关键 Getters（约 40 个）

- `activeConversation` / `activeRequirement` / `messages`：当前会话及其关联需求、渲染消息
- `isChatInputEnabled` / `canOperateActiveConversation`：输入框可操作性（综合 readonly、完成态、stake、review 状态）
- `canDispatchTask` / `canAcceptTask` / `canRejectTask` / `canTransferTask`：工作流动作权限
- `canSubmitReviewAction` / `canApproveReviewAction` / `canRejectReviewAction`：PRD 审核动作
- `sessionTree` / `sessionTreeBySpace`：左侧会话树（按空间分组）
- `filteredPoolBusinessCards` / `filteredPoolTasks`：泳道过滤（关键词 + 空间）
- `progressDocTabs` / `activeProgressDocTab`：进度抽屉文档 Tab
- `isActiveDocumentWritable` / `documentStatusText`：文档编辑权限与状态文案

#### 关键 Actions（约 80 个）

| 类别 | 代表方法 |
|---|---|
| 认证 | `login`、`logout`、`beginReauthentication`、`restoreAuthRecovery`、`resetUserContext` |
| 空间 | `loadProjects`、`loadWorkspaceList`、`createSpace`、`deleteSpace`、`confirmRenameSpace`、`moveRequirementToSpace` |
| 会话列表 | `loadWorkspaceSessionList`、`ensureWorkspaceSessionList`、`invalidateWorkspaceSessionList`、`fetchWorkspaceSessionListData` |
| 会话进入 | `openConversation`、`openRequirement`、`openTodoRequirement`、`enterWorkspace`、`showWorkspaceSession` |
| Harness 恢复 | `restoreHarnessSession`、`loadHarnessSessionData`（并发拉取 history/status/session/children/questions/permissions/dispatch/systemSelection/taskAcceptance） |
| 需求创建 | `createBusinessDemand`、`createConversation`、`discardCreatedConversation`、`deleteRequirementSession` |
| 派发 | `startDocDispatch`、`confirmDispatchSuggestion`、`cancelDispatchSuggestion`、`confirmSystemSelection` |
| 任务承接 | `rejectTask`、`withdrawTask`、`transferTask`、`startPrdFromAssignmentCard`、`openAcceptedPrdSession`、`retryTaskAcceptanceNavigation` |
| PRD 审核 | `submitReview`、`approveReview`、`returnReview`、`runAiReviewAction`、`continueProductRevision` |
| 技术拆解 | `refreshTechnicalBreakdownOffer`、`startTechnicalBreakdown` |
| 资产 | `runAssetSearch`、`loadMoreAssetResults`、`loadAssetMatrix`、`loadAssetTopics`、`loadAssetFunctions`、`openAssetDomainTopic`、`openBusinessFunctionDetail` |
| 文档 | `getDocContent`、`setDocContent`、`setDocOutline`、`downloadActiveDoc`、`progressDocContent` |
| 布局 | `syncWorkspaceViewportMode`、`focusChatWorkspace`、`focusDocWorkspace`、`toggleChatDocFocus`、`applyNarrowWorkspaceLayout` |
| 进度/日志 | `openProgressDrawer`、`fetchProgressList`、`refreshRequirementContext`（日志） |
| 待办 | `loadMoreHomeTodoItems`、`removeRequirementFromTodo` |

#### 并发控制与竞态防护

- **userContextVersion**：每次切换用户/登出 +1，所有异步回调完成后比对 `this.userContextVersion`，过期直接丢弃
- **conversationEntryRequestId**：会话进入请求序号，防止 A/B 两次 openConversation 交叉
- **AbortController**：`harnessSessionRestores`（WeakMap）、`scheduleRefreshInFlight`（WeakMap）、`dispatchResultControllers`（Map）
- **请求去重**：`workspaceListRequests`（WeakMap）合并相同 key 的并发调用
- **in-flight 防抖**：`appToolCardActionsInFlight`（Set）防止同一工具卡重复操作

### 4.2 会话同步 Store（`stores/conversationSync.ts`）

独立 Pinia store，维护 Harness 会话的**不可变事件归约状态**：

- 数据源：SSE 事件流（`eventStream.ts`）+ REST 快照（history、status、children、todo、questions、permissions、dispatch suggestion、system selection、task acceptance cards）
- 状态：`message` / `part` / `toolCard` / `task` / `question` / `permission` / `harnessSession` / `harnessChildren` / `sessionTodo` / `businessError`
- 优化：`optimistic.message/part`（发送中的乐观消息，2min 确认窗口）、消息内容缓存（WeakMap by revision）、工具卡折叠（同 requirementId+brdSessionId 只保留最新 dispatch-suggestion / system-selection）
- 显示：`displayMessagesForScope(scopeId, userName, leaderId)` 将多 session 事件合并为单一时间线

### 4.3 其他 Store

- `delivery.ts`：BRD 审核清单（`fetchDelivery` / `deliveryReview`），含版本比对
- `attachmentDraft.ts`：附件草稿（按 userId+sessionId 隔离），支持上传队列、解析、重试

## 5. 实时通信设计（SSE）

### 5.1 事件流（`services/eventStream.ts`）

- 协议：HTTP POST → SSE 流（Harness 网关）
- 心跳：服务端每 10s 发 ping；客户端 35s 无数据视为 stale → 主动断开重连并补拉历史
- 重连：指数退避 250ms → 10s，健康后重置；403/404 连续 3 次放弃（鉴权类错误不重试）
- 事件归一化：`harnessEventAdapter.normalizeHarnessEvent(raw) → ConversationEvent`
- 批量刷新：`FLUSH_FRAME_MS = 16ms`（requestAnimationFrame 对齐）
- 鉴权：每个 session 独立 `X-User-Token` + `directory`，存于内存 Map（`harnessSessionUserTokens` / `harnessSessionDirectories`）

### 5.2 事件类型（`types/conversation.ts`）

```
message.updated / message.part.updated / message.part.delta
tool.card.updated / tool.card.removed
task.updated
question.updated / question.answered
permission.requested / permission.responded
business.error
session.status.updated
schedule.updated
```

### 5.3 会话恢复流程（`restoreHarnessSession`）

进入会话时并发拉取 9 组数据（`Promise.allSettled`）：

1. `fetchConversationHistory(sessionId, {limit:50})` — 消息历史
2. `fetchSessionStatus(signal, sessionId)` — 各 session 状态
3. `fetchHarnessSession(sessionId, signal)` — 会话元信息
4. `fetchHarnessSessionChildren(sessionId, signal)` — 子会话树（BFS，每层最多 3 并发，带版本缓存）
5. `fetchPendingQuestions(signal, sessionId)` — 待回答问题
6. `fetchPendingPermissions(signal, sessionId)` — 待授权请求（自动允许白名单外的）
7. `fetchRequirementDispatchSuggestion(sessionId, signal)` — 派发建议卡
8. `fetchRequirementSystemSelection(sessionId, signal)` — 系统选择卡
9. `fetchRequirementTaskAcceptanceCards(sessionId, signal)` — 任务承接卡

附加：`refreshHarnessSchedule` + `fetchHarnessSessionTodo`（optional，不阻塞主流程）

全部 fulfilled → `complete=true`；任一 rejected → `conversationSyncError` 提示用户。

## 6. 业务工作流设计

### 6.1 需求生命周期

```
[首页/项目] 创建需求
     │
     ▼
业务需求会话（BRD 撰写中）
  ├── AI Agent 协助：需求澄清 → BRD 草拟
  ├── 业务经理编辑 BRD（Tiptap 协同编辑器，Yjs 实时同步）
  └── BRD 前四章确认后 → 触发派发
     │
     ▼
派发阶段
  ├── AI 生成派发建议卡（dispatch-suggestion card）
  │   ├── 系统选择卡（system-selection card）：为每个任务选承接系统
  │   └── 确认负责人（mention 候选人列表）
  ├── 业务经理在卡上确认 → uploadRequirementCurrentBrd → sendConfirmationMessage
  └── 取消派发 → cancelRequirementDispatchSuggestion
     │
     ▼
需求待承接（任务分发给产品经理）
  ├── 产品经理收到 task-acceptance card
  ├── 操作：承接 / 拒绝（填原因）/ 转派（选新人）/ 撤回
  └── 承接成功 → 自动进入 PRD 会话（openAcceptedPrdSession，轮询 3 次等 prdSessionId 出现）
     │
     ▼
产品拆解（PRD 撰写中）
  ├── AI Agent 协助：产品定义 → 业务流程 → 功能矩阵 → 功能细节 → 质量审查
  ├── 产品经理编辑 PRD（Tiptap 协同编辑器）
  └── PRD 退回修改 → 继续修改（continueProductRevision）
     │
     ▼
业务审核中
  ├── 产品经理提交审核（SUBMIT_REVIEW）
  ├── 业务经理审核：通过（REVIEW_APPROVE）/ 退回（REVIEW_REJECT + 原因）
  └── 审核通过 → 已完成
     │
     ▼
已完成
  └── 可选：启动技术功能点拆解（startTechnicalBreakdown）
```

### 6.2 泳道映射（`_mapTaskStatusToLane`）

| 任务状态（中文） | 泳道 |
|---|---|
| 撰写中 / 已承接 | 业务需求 |
| 待承接 | 需求待承接 |
| 拆解中 / 退回修改 | 产品拆解 |
| 待业务审核 | 业务审核中 |
| 已完成 | 已完成 |

### 6.3 权限模型

- **stake 判定**（`conversationStakeForUser`）：根据需求 creator / part.owner 判断当前用户是 `business` 还是 `product`
- **allowedActions**：由 Harness schedule 下发（`sync.task[taskId].allowedActions`），前端 `canRunAction(action, {allowedActions, fallback})` 双重校验
- **readonly 标志**：会话级 `conversation.readonly`，已完成泳道进入时锁定输入
- **发起人保护**：`ownsRequirementFromState` 基于 `creatorUserId` 精确匹配（非姓名回退）

### 6.4 空间（工作空间）设计

- 空间 = 业务域隔离单位，对应后端 `workspaceId`
- 默认空间（`isDefault` 或名称「默认空间」）不可删除/重命名
- 需求归属空间：`spaceAssignments[requirementId] → spaceId`，持久化到 localStorage + 后端 `transferRequirement`
- 侧栏按空间分组展示会话树；首页/工作台支持空间筛选

3. 派发建议卡待确认（`dispatchSuggestionBlocksComposer`）

#### 本地未保存变更模型

| 数据结构 | 用途 | 提交时机 |
|---|---|---|
| `localStatusOverrides: Map<featureId, status\|null>` | 确认/取消确认状态覆盖 | 确认时 `batchSave(syncStatus=1)` |

| `addedNodes: Map<featureId, AppNode[]>` | 新增节点 | 确认/全部确认时 `deleteFlag=false` |

## 8. 认证与安全设计

### 8.1 登录方式

1. **账号密码**（`/login`）：`POST /apbm/auth/login` → 返回 userId、ssoNo、realname、token
2. **SSO Token**（`/tglogin?token=…`）：天弓客户端传递 URL 编码 token
3. **旧路径兼容**：`/tglogin`、`/tglogin/`、`/tglogin/index.html` → Nginx rewrite → `index.html` → 前端 `legacyTgloginUrl` 转为 `#/tglogin?token=…`

### 8.2 Token 管理

- 业务后端：`X-RMPF-Access-Token` + `X-RMPF-SSO-No` 请求头，localStorage 持久化
- Harness：每会话独立 JWT（`harnessUserToken`），内存 Map 按 sessionId 隔离；过期时 `refreshHarnessUserToken` 续期
- 身份隔离：JWT claims（iss+sub）解码为 subject，不同用户 token 不会串用

### 8.3 过期恢复（authRecovery）

- `verifyBusinessSession` 定期校验；过期 → `beginReauthentication`
- 保存恢复上下文（userId、ssoNo、sessionId、cardKey、draft、attachments）到 sessionStorage
- 重新登录后 `restoreAuthRecovery` 恢复原会话 + 草稿
- Electron 客户端通知：`electronAPI.sendMessage('login'/'logout', …)`

### 8.4 安全约束

- 敏感凭证（token）不写入 console（仅 fingerprint + length）
- XSS 防护：markdown 渲染经 `dompurify` 清洗
- 权限操作前后双重校验（前端 allowedActions + 后端接口鉴权）
