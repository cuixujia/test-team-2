## 2. 背景与依据

### 2.1 需求背景

杭州银行各业务部门在系统建设过程中，存在大量系统建设需求需要通过科技/IT部门统一承接。当前需求管理面临以下核心问题（来源：BRD 第一章「需求背景」）：

1. **需求入口分散、缺乏统一归口**：各部门通过邮件、IM、线下等多种渠道提出系统建设需求，无法集中查看和统计，科技/IT部门难以全面掌握需求全貌。
2. **需求状态不透明**：业务方不清楚自己提出的需求进展到哪一步，需要频繁询问科技/IT部门，沟通成本高，影响业务协作效率。
3. **历史需求无法沉淀复用**：过往需求资料散落各处，新需求难以参考相似案例，存在重复建设的风险。

为系统性解决上述问题，拟建设「杭州银行系统需求管理平台」，面向科技/IT部门提供统一的系统建设需求管理能力，实现需求的统一受理、规范评审和进度透明跟踪。

## 4. 业务流程总览

### 4.1 主流程总览

杭州银行系统需求管理平台的业务主流程覆盖从需求提出到完成的完整生命周期，以需求为核心业务对象，以任务和功能点为派生对象，形成"提出→派发→承接→拆解→跟踪"的端到端闭环。

```
业务部门提出需求 → 需求派发与任务承接 → 技术功能点拆解 → 进度跟踪与查询
```

**主流程链路说明：**

1. **需求提出**：业务部门通过平台统一入口创建系统建设需求，需求进入「待沟通」状态，系统自动生成需求 ID 和 BRD 协作会话。
2. **需求派发与任务承接**：派发人将需求转化为任务并指定承接人，任务进入「待承接」状态；承接人确认承接后任务进入「处理中」状态。
3. **技术功能点拆解**：承接人将已承接的需求拆解为可独立开发的技术功能点，管理拆解状态并绑定存量资产。
4. **进度跟踪与查询**：用户查询需求进度、访问工作台、查询资产信息或查看待办列表，系统返回对应数据。

**关联存量功能：** 需求管理（FUN202610122109339565133516802）、需求派发（FUN202610122109326406259691522）、任务流转与处理（FUN202610122109340093477408769）、业务视图与功能点管理（FUN202610122109330181304012801）、需求进度跟踪（FUN202610122109340339611750401）、工作台概览（FUN202610122109331484244824065）、资产检索（FUN202610122109332639570055170）、待办事项管理（FUN202610122109332084026101761）。

### 4.2 各业务事件说明

#### 4.2.1 事件一：需求提出与创建

| 要素 | 说明 |
| --- | --- |
| 事件名称 | 需求提出与创建 |
| 事件类型 | 业务发起事件 |
| 干系人 | 业务部门用户（需求发起人） |
| 目的 | 业务部门通过平台统一入口创建系统建设需求，启动需求管理流程 |
| 触发条件 | 业务部门有系统建设需求时主动发起 |
| 前置条件 | 用户已登录系统并具有相应工作空间的访问权限；已指定有效的工作空间 ID |
| 输入 | 工作空间 ID、需求标题（可选，未提供时系统自动生成默认标题） |
| 应答 | 系统返回需求 ID 和 BRD 协作会话信息 |
| 结果 | 需求创建成功，进入「待沟通」状态（PENDING），系统生成需求 ID 和 BRD 协作会话 |
| 关联功能 | 需求管理（FUN202610122109339565133516802） |

**业务流程：**

1. 业务用户发起新增需求，输入工作空间 ID 和可选的需求标题。
2. 系统调用 HARNESS 服务创建 BRD 协作会话，包括用户同步、Token 获取、工作空间配置和群聊会话创建，HARNESS 返回会话 ID、BRD 工作空间 ID、Access Token 等信息，系统将 Access Token 保存到缓存中。
3. 系统构建需求实体并插入数据库，设置需求 ID、标题、发起人信息、状态为待处理（PENDING）、BRD 会话信息等，记录操作日志。
4. 需求进入「待沟通」状态，等待需求派发。

**异常分支：** 参数校验失败时操作被拒绝且用户收到明确的错误提示；权限不足时操作被拒绝。

#### 4.2.2 事件二：需求派发与任务承接

| 要素 | 说明 |
| --- | --- |
| 事件名称 | 需求派发与任务承接 |
| 事件类型 | 业务流转事件 |
| 干系人 | 科技/IT 部门产品管理人员（派发人）、产品经理或技术负责人（承接人） |
| 目的 | 将需求转化为具体工作任务并分配给承接人，承接人确认承接后任务进入处理阶段，承接人完成处理后提交审核 |
| 触发条件 | 需求已创建并上传 BRD 文档 |
| 前置条件 | 需求存在且有效；BRD 文档已上传并生成版本 ID；派发时必须使用需求的最新 BRD 文档版本；承接人 SSO 号有效 |
| 输入 | 需求 ID、BRD 文档版本 ID、任务列表（任务名称、技术负责人 SSO 号、系统编码、系统名称、领域编码、领域名称） |
| 应答 | 系统返回需求 ID 和所有任务的派发结果列表 |
| 结果 | 任务被承接人确认承接，进入「处理中」状态；承接人完成处理后提交审核，任务流转到「待审核」状态 |
| 关联功能 | 需求派发（FUN202610122109326406259691522）、任务流转与处理（FUN202610122109340093477408769）、任务承接状态管理（FUN202610122109327382592999425） |

**业务流程：**

**派发阶段：**

1. 派发人选择已创建的需求发起派发操作，输入 BRD 文档版本 ID 和任务列表。
2. 系统校验派发请求：需求 ID、BRD 文档版本 ID、任务列表必填项完整；查询需求确认存在且有效；查询最新 BRD 文档版本确认传入版本 ID 与最新版本一致；批量查询承接人用户信息确认所有承接人账号有效。
3. 系统删除原有的需求-领域关联关系，根据任务列表中的领域信息全量插入新的需求-领域关联记录。
4. 对于复用任务（状态为已拒绝/已撤回），系统恢复任务状态为待承接并更新相关信息；对于新任务，系统生成任务 ID 并插入数据库。
5. 系统为每个任务保存与业务领域的关联关系，更新需求的当前 BRD 文档版本 ID，需求保持处理中（PROCESSING）状态。
6. 系统调用待办网关服务为所有承接人批量创建待办事项（包含任务名称、派发人、接收人、回调地址等），推送渠道包含站内消息。待办网关调用失败时记录日志但不阻断主流程。

**承接阶段：**

7. 承接人在待办列表中收到任务通知，可执行以下操作：
  - **承接**：校验任务状态为待承接且当前用户为承接人，创建 PRD 工作空间和会话，任务状态更新为处理中，向派发人发送承接通知。
  - **拒绝**：填写拒绝理由，任务状态更新为已拒绝，向派发人发送拒绝通知。
  - **转派**：选择新承接人并填写转派理由，校验新承接人存在且不为当前用户，更新任务承接人信息，为新承接人创建待办事项。
8. 派发人可执行**撤回**操作：填写撤回理由，校验任务状态为待承接且当前用户为派发人，任务状态更新为已撤回。

**提交审核阶段：**

9. 承接人完成任务处理（包括 PRD 文档编写等）后，提交审核。系统校验任务状态为处理中且当前用户为承接人，任务状态从处理中流转到待审核，通知需求发起人进行业务审核。

**异常分支：** BRD 文档版本过期时派发被拒绝；仅待承接状态的任务可被承接/拒绝/转派/撤回；任务标题不能为空且长度不超过 25 字符；拒绝理由不能为空且长度不超过 512 字符。

#### 4.2.3 事件三：技术功能点拆解

| 要素 | 说明 |
| --- | --- |
| 事件名称 | 技术功能点拆解 |
| 事件类型 | 业务处理事件 |
| 干系人 | 产品经理或技术负责人（承接人） |
| 目的 | 将审核通过的任务拆解为可独立开发的技术功能点，管理拆解状态，功能点可绑定存量服务或函数资产 |
| 触发条件 | 任务已通过业务审核，进入「审核完成」状态 |
| 前置条件 | 任务状态为审核完成；用户已登录系统并具有相应域或子系统的访问权限 |
| 输入 | 子系统/域 ID、模块 ID、功能组 ID、功能点信息（名称、描述、业务流程） |
| 应答 | 系统返回功能点列表和详情信息 |
| 结果 | 需求下的功能点拆解完成，所有功能点状态更新为「已拆解」，任务流转到拆解完成 |
| 关联功能 | 业务视图与功能点管理（FUN202610122109330181304012801）、业务功能信息管理（FUN202610122109340893238906881） |

**业务流程：**

1. 承接人进入业务视图管理界面，通过域 ID 查询子系统下的模块列表，选择目标模块后查询功能组列表，再选择功能组查询功能点列表。
2. 承接人查看功能点详情：系统通过 RPC 调用获取功能点的完整信息（服务名称、URL、模块、功能组、方法签名、调用出度统计等），帮助承接人了解现有功能点的能力。
3. 承接人可更新功能点的名称、描述和业务流程实现说明：系统校验功能点 ID、名称、描述均为必填项，通过 RPC 调用 APAM 子系统执行异步更新；更新业务流程时检查是否存在进行中的 AI 分析记录，若存在则拒绝更新以防数据冲突。
4. 承接人完成 PRD 文档章节拆分后，系统自动或由用户手动触发保存业务功能信息到 MySQL 数据库和 Elasticsearch 索引，包含任务 ID、需求 ID、功能标题、功能内容等。
5. 功能点可绑定存量服务或函数资产：雪狼系统在立项审批完成后回调本平台，更新业务功能的立项信息和状态（绑定/变更/解绑）。
6. 按迭代统计拆解进度，跟踪待拆解和已拆解的功能点数量。
7. 所有关联功能点拆解完成后，任务状态从拆解中流转到拆解完成，拆解完成是任务终态。

**异常分支：** 域 ID 为空时返回空列表；功能点不存在时返回空对象；AI 分析进行中时禁止更新业务流程；ES 保存失败不影响 MySQL 主流程。

| 结果 | 系统返回查询结果，不涉及需求或任务状态的变更 |
| 关联功能 | 需求进度跟踪（FUN202610122109340339611750401）、工作台概览（FUN202610122109331484244824065）、资产检索（FUN202610122109332639570055170）、资产血缘查询（FUN202610122109335557996138498）、资产相似推荐（FUN202610122109335116847632386）、待办事项管理（FUN202610122109332084026101761）、任务流转与处理（FUN202610122109340093477408769） |

**业务流程：**

**需求进度查询：**

1. 业务用户提供需求 ID，发起查询需求进度的请求。
2. 系统验证需求 ID 非空且需求存在，以泳道分组形式返回进度列表：
  - 第 1 泳道（需求概览）：需求基本信息及该需求下所有有效任务清单。
  - 第 2 泳道（待承接任务）：状态为待承接的任务列表。
  - 第 3 泳道（处理中任务）：状态为处理中或业务已拒绝的任务列表。
  - 第 4 泳道（待审核任务）：状态为待审核的任务列表。
  - 第 5 泳道（审核完成任务）：状态为审核完成、拆解中或拆解完成的任务列表。

**需求工作台：**

3. 业务用户登录系统后访问工作台首页，系统从用户会话中获取当前登录用户的 SSO 账号。
4. 系统并行查询五个工作泳道的数据和用户工作空间列表：
  - 泳道 1（待沟通需求）：用户发起的待处理需求，以及存在撤回或产品拒绝任务的需求。
  - 泳道 2（待接收任务）：用户作为承接人且状态为待接收的有效任务。
  - 泳道 3（处理中任务）：用户参与的处于处理中或业务拒绝状态的有效任务。
  - 泳道 4（待审核任务）：用户参与的处于待审核状态的有效任务。
  - 泳道 5（审核完成任务）：用户参与的处于审核完成、拆解中或拆解完成状态的有效任务。
5. 每个工作项附带 Harness 会话令牌，支持快速跳转到 BRD/PRD 会话界面。
6. 系统查询用户工作空间列表，展示各工作空间的任务和需求数量统计；按工作空间分组展示会话列表。

**需求资产查询：**

7. 业务用户进入资产检索页面，通过关键词检索 BRD/PRD/FDD 三类资产。
8. 点击资产卡片查看详情：系统查询资产的领域标签、主题活动标签和价值链标签（调用架构网关巨象接口，失败时降级为空列表）。
9. 查看相似资产：系统根据源资产的类型和 ID 查找同标签的相似资产（BRD/PRD 按领域编码，FDD 按主题活动），结果去重后按创建时间倒序返回。
10. 查看资产血缘：系统按资产类型执行差异化查询策略，将需求→任务→功能组装为层级血缘树并标记当前查询节点。

**待办信息查询：**

11. 用户查询当前待办事项列表：系统调用待办网关查询接口（交易码 ACTION65），返回待办事项列表及分页信息。
12. 任务流转与处理功能同时提供个人待办任务查询：查询当前用户作为承接人且状态为待承接或待审核的有效任务，按更新时间降序排序返回分页结果。
13. 用户可按状态筛选待办事项，支持快速跳转处理。

**异常分支：** 需求 ID 为空或需求不存在时返回空列表；资产类型不合法时提示错误；资产不存在或已失效时提示资产不存在；待办网关调用失败时提示网关调用异常；价值链标签获取失败时降级为空列表不影响主流程。

### 4.3 需求状态流转

#### 4.3.1 需求状态流转

| 当前状态 | 可流转到 | 触发操作 | 关联功能 |
| --- | --- | --- | --- |
| 待沟通（PENDING） | 处理中（PROCESSING） | 科技/IT 发起需求派发 | 需求派发 |
| 处理中（PROCESSING） | 已完成（COMPLETED） | 所有关联任务完成 | 任务流转与处理 |
| 处理中（PROCESSING） | 已取消（CANCELLED） | 需求被删除（软删除） | 需求管理 |

**状态说明：**

- **待沟通（PENDING）**：需求创建后的初始状态，等待需求派发。仅此状态允许修改标题和业务领域。需求派发后流转到处理中状态。
- **处理中（PROCESSING）**：需求派发后进入此状态，需求处于任务执行阶段。派发成功后需求保持处理中状态。
- 需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成。
- **已取消（CANCELLED）**：需求被删除时采用软删除机制（valid_flag 置为 0），状态更新为已取消。需求下存在进行中（非已拒绝/已撤回）的有效任务时禁止删除。

#### 4.3.2 任务状态流转

| 当前状态 | 可流转到 | 触发操作 | 操作人 | 关联功能 |
| --- | --- | --- | --- | --- |
| 待承接 | 处理中 | 承接人确认承接 | 承接人 | 任务流转与处理 |
| 待承接 | 已拒绝 | 承接人拒绝任务 | 承接人 | 任务流转与处理 |
| 待承接 | 已撤回 | 派发人撤回任务 | 派发人 | 任务流转与处理 |
| 处理中 | 待审核 | 承接人完成处理后提交审核 | 承接人 | 任务流转与处理 |
| 待审核 | 审核完成 | 业务审核通过 | 需求发起人 | 任务流转与处理 |
| 待审核 | 业务已拒绝 | 业务审核拒绝 | 需求发起人 | 任务流转与处理 |
| 审核完成 | 拆解中 | 审核通过后承接人开始技术功能点拆解 | 承接人 | 任务流转与处理 |
| 拆解中 | 拆解完成 | 所有关联功能点拆解完成 | 承接人 | 任务流转与处理 |
| 业务已拒绝 | 处理中 | 承接人修改任务后重新提交审核 | 承接人 | 任务流转与处理 |

**状态说明：**

- **待承接**：任务创建后的初始状态，等待承接人决策。仅此状态可被承接、拒绝、转派或撤回。
- **处理中**：承接人确认承接后进入此状态，承接人开始处理任务。仅待承接或处理中状态可修改任务标题。承接人完成处理后提交审核，流转到待审核状态。
- **待审核**：承接人完成处理后提交审核进入此状态，等待需求发起人进行业务审核。
- **审核完成**：业务审核通过后任务状态变为审核完成，任务进入拆解阶段，承接人可开始技术功能点拆解。当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成。
- **拆解中**：从审核完成流转到此状态，承接人在此状态下执行功能点拆解操作。
- **拆解完成**：所有关联功能点拆解完成后流转到此状态，是任务终态。
- **已拒绝**：承接人拒绝承接任务，需由派发人重新派发或调整任务分配。
- **已撤回**：派发人撤回已派发的任务，需重新分配。
- **业务已拒绝**：需求发起人业务审核拒绝，任务回到处理中状态，承接人可修改任务后重新提交审核。

#### 4.3.3 功能点拆解状态流转

| 当前状态 | 可流转到 | 触发操作 | 关联功能 |
| --- | --- | --- | --- |
| 待拆解 | 已拆解 | 承接人完成功能点拆解并绑定资产 | 业务视图与功能点管理、业务功能信息管理 |
| 已拆解（全部） | 拆解完成（任务） | 所有关联功能点拆解完成 | 任务流转与处理 |

**状态说明：**

- **待拆解**：任务被承接后，需求下的功能点初始状态为待拆解，等待承接人进行技术功能点拆解。
- 所有关联功能点拆解完成后，任务进入拆解完成状态（终态）。

#### 4.3.4 状态流转约束

| 约束项 | 说明 |
| --- | --- |
| 需求完成约束 | 当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成，需求状态更新不影响已审核完成或拆解完成的任务 |
| 删除限制 | 需求下存在进行中（非已拒绝/已撤回）的有效任务时禁止删除 |
| 修改限制 | 仅待处理或处理中状态的需求允许修改标题和业务领域，已完成和已取消状态禁止修改 |
| 派发约束 | 派发时必须使用需求的最新 BRD 文档版本，基于过期版本派发被拒绝 |
| 承接约束 | 仅待承接状态的任务可被承接/拒绝/转派，不能转派给自己 |
| 审核约束 | 仅待审核状态的任务可执行业务审核，审核通过后任务进入拆解阶段（流转到拆解中），审核拒绝后任务回到处理中状态，承接人修改后重新提交审核 |
| 拆解约束 | 仅审核完成状态的任务可开始技术功能点拆解，所有功能点拆解完成后流转到拆解完成（终态），拆解完成不再回退 |
| 任务复用 | 仅允许复用状态为已拒绝或已撤回的任务，复用时恢复状态为待承接并清空拒绝/撤回原因 |
| 待办同步 | 待办功能支持开关控制，禁用时跳过待办创建或更新，待办同步失败不影响主流程 |
| 消息通知 | 消息通知功能支持配置开关，禁用时跳过消息创建但不影响主流程 |

## 6. 业务功能

### M01 需求创建与管理

模块编号：M01。覆盖需求从创建、BRD文档版本管理、状态流转到存档的完整前置生命周期，业务对象为需求，管理目标为需求创建、状态流转和台账存档。

#### F01 需求创建与受理

**业务流程：**

1. 业务部门用户通过平台统一入口发起新增需求，输入工作空间 ID 和可选的需求标题。
2. 系统调用外部 HARNESS 服务创建 BRD 协作会话（用户同步、Token 获取、工作空间配置、群聊会话创建），获取会话 ID、BRD 工作空间 ID 和 Access Token 并保存到缓存。
3. 系统构建需求实体并插入数据库，设置需求 ID、标题（未提供时自动生成默认标题）、发起人信息、状态为待处理（PENDING）、BRD 会话信息等，记录操作日志。
4. 需求进入「待沟通」状态，等待科技/IT 部门发起需求派发。
5. 科技/IT 部门产品管理人员集中接收需求，对需求进行业务领域归类：输入需求 ID 和业务领域 ID 列表，系统采用先删除后插入的全量更新策略更新需求与领域的关联关系。
6. 受理人可修改需求标题和维护需求信息：校验必填项和长度不超过 25 字符，验证当前用户为科技/IT 受理人或发起人后更新标题和需求信息。
7. 需求完成业务领域分类后，由科技/IT 部门发起需求派发时进入「处理中」状态。

**业务规则：**

- 需求创建时工作空间 ID 为必填项，需求标题可选，未提供时系统自动生成默认标题。
- 业务领域关联采用全量更新策略（先删除后插入），确保关联关系与最新输入一致。
- 仅待处理（PENDING）或处理中（PROCESSING）状态的需求允许修改标题和业务领域；已完成和已取消状态禁止修改。
- 科技/IT 受理人可修改需求标题和维护需求信息（包括业务领域归类），发起人可修改自身创建的需求标题和需求信息。
- 参数校验失败或权限不足时操作被拒绝，用户收到明确的错误提示。

**业务对象：** 需求（需求 ID、标题、发起人、工作空间 ID、状态、BRD 会话信息、业务领域关联）

**业务界面：** 需求创建入口、需求受理登记页面。无独立界面说明的存量功能由现有界面承载，本次不新增界面。

**完成标准：** 业务部门可通过统一入口成功创建需求并自动绑定 BRD 协作会话，科技/IT 部门受理人可修改需求标题、维护需求信息并完成业务领域分类，需求正确流转到「处理中」状态。

**涉及存量功能编码清单：** FUN202610122109339565133516802（需求管理）、FUN202610122109325829341564930（需求业务领域关联管理）

#### F02 需求状态流转与BRD文档管理

**业务流程：**

1. 需求创建并绑定 BRD 协作会话后，业务用户上传 BRD 文档：指定需求 ID 和文档类型（BRD），系统校验必填项和文档类型合法性。
2. 系统生成 MinIO 对象名称和唯一文档版本号（同一需求下从 1 开始递增），调用 MinIO SDK 上传文件并构建访问 URL，在文档版本表中插入新记录并更新需求的当前 BRD 文档版本 ID。
3. 需求状态流转：需求从「待沟通」状态开始，科技/IT 部门发起需求派发时需求流转到「处理中」状态。
4. 当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动流转到「已完成」。
5. 需求可被取消，状态流转到「已取消」。

**业务规则：**

- 评审协作由外部 HARNESS 服务承接，SYS_DAPR 不再包含评审功能。
- BRD 文档类型必须合法，不合法时上传被拒绝。
- BRD 版本号在同一需求下从 1 开始递增，每次上传生成新版本。
- 需求状态流转链路：待沟通→处理中→已完成/已取消，不再包含"待评审"状态。
- 需求完成约束：当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成。

**业务对象：** BRD 文档（文档版本号、文档类型、MinIO 对象名称、访问 URL）、需求状态（待沟通/处理中/已完成/已取消）

**业务界面：** BRD 文档上传入口、需求状态展示。评审协作界面由外部 HARNESS 承载，不在 SYS_DAPR 范围内。

**完成标准：** BRD 文档可成功上传并生成版本记录，需求状态按待沟通→处理中→已完成/已取消正确流转，评审协作由外部 HARNESS 承接不再作为 SYS_DAPR 功能。

**涉及存量功能编码清单：** FUN202610122109339565133516802（需求管理）

#### F03 需求台账存档

> **变化类型：调整。** 存量需求管理功能已具备需求记录持久化和操作日志（创建时插入数据库记录、状态流转全程记录、软删除保留数据 valid_flag=0），本次调整新增独立台账查询入口。

**业务流程：**

1. 需求创建时系统自动将需求记录持久化到数据库（需求 ID、标题、发起人、状态、BRD 会话信息等），并记录操作日志。
2. 需求状态流转全程（待沟通→处理中→已完成/已取消）均自动记录操作日志，形成完整的处理记录链。
3. 需求被删除时采用软删除机制（valid_flag 置为 0），状态更新为已取消，数据保留不物理删除。
4. **本次新增**：用户通过独立台账查询入口查询所有经平台受理的需求及其处理记录，支持按需求状态、业务领域、时间范围等条件筛选。

**业务规则：**

- 所有经平台受理的需求及其处理记录自动存档，无需人工触发。
- 需求删除采用软删除机制，保留数据可追溯，不物理删除。
- 需求下存在进行中（非已拒绝/已撤回）的有效任务时禁止删除。
- **本次调整新增**：台账查询支持按需求状态（待沟通/处理中/已完成/已取消）、业务领域、时间范围等条件组合筛选。
- 软删除的需求（valid_flag=0）在台账中可见，标记为已取消状态。

**业务对象：** 需求台账记录（需求 ID、标题、发起人、状态、业务领域、创建时间、操作日志、有效标识）

**业务界面：** 本次调整新增独立台账查询页面，提供筛选条件输入和结果列表展示。存量存档行为由系统自动完成，无需独立界面。

**完成标准：** 存量自动存档行为保持不变；本次调整后用户可通过独立台账查询入口查询所有经平台受理的需求及其处理记录，支持按需求状态、业务领域、时间范围等条件筛选，软删除数据可追溯。

**涉及存量功能编码清单：** FUN202610122109339565133516802（需求管理）

### M02 需求派发与任务承接

模块编号：M02。业务对象为任务，管理目标为派发、承接、转派和撤回，覆盖任务从创建到承接确认的流转生命周期。

#### F04 需求派发

**业务流程：**

1. 派发人选择已创建并上传 BRD 文档的需求发起派发操作，输入 BRD 文档版本 ID 和任务列表（任务名称、技术负责人 SSO 号、系统编码、系统名称、领域编码、领域名称）。
2. 系统校验派发请求：需求 ID、BRD 文档版本 ID、任务列表必填项完整；查询需求确认存在且有效；查询最新 BRD 文档版本确认传入版本 ID 与最新版本一致；批量查询承接人用户信息确认所有承接人账号有效。
3. 系统删除原有的需求-领域关联关系，根据任务列表中的领域信息全量插入新的需求-领域关联记录。
4. 对于复用任务（状态为已拒绝/已撤回），系统恢复任务状态为待承接并更新相关信息；对于新任务，系统生成任务 ID 并插入数据库。
5. 系统为每个任务保存与业务领域的关联关系，更新需求的当前 BRD 文档版本 ID，需求保持处理中（PROCESSING）状态。
6. 系统调用待办网关服务为所有承接人批量创建待办事项（包含任务名称、派发人、接收人、回调地址等），推送渠道包含站内消息。待办网关调用失败时记录日志但不阻断主流程。

**业务规则：**

- 派发时必须使用需求的最新 BRD 文档版本，基于过期版本派发被拒绝。
- 任务标题不能为空且长度不超过 25 字符。
- 仅允许复用状态为已拒绝或已撤回的任务，复用时恢复状态为待承接并清空拒绝/撤回原因。
- 承接人 SSO 号必须有效，系统批量查询确认所有承接人账号有效后才执行派发。
- 需求-领域关联采用全量更新策略（先删除后插入）。
- 待办网关调用失败时记录日志但不阻断主流程；待办功能支持开关控制，禁用时跳过待办创建。
- 消息通知功能支持配置开关，禁用时跳过消息创建但不影响主流程。

**业务对象：** 任务（任务 ID、任务名称、承接人 SSO 号、系统编码、领域编码、状态）、需求-领域关联、BRD 文档版本 ID、待办事项

**业务界面：** 需求派发操作页面，输入 BRD 版本和任务列表。无独立界面说明的存量功能由现有界面承载，本次不新增界面。

**完成标准：** 已创建并上传 BRD 文档的需求可成功派发给指定承接人，任务正确创建并进入待承接状态，承接人收到待办通知，需求状态正确流转到处理中。

**涉及存量功能编码清单：** FUN202610122109326406259691522（需求派发）

#### F05 任务承接处理

**业务流程：**

1. 承接人在待办列表中收到任务通知，可执行以下操作：
  - **承接**：系统校验任务状态为待承接且当前用户为承接人，创建 PRD 工作空间和会话，任务状态更新为处理中，向派发人发送承接通知。
  - **拒绝**：承接人填写拒绝理由，系统校验理由不能为空且长度不超过 512 字符，任务状态更新为已拒绝，向派发人发送拒绝通知。
  - **转派**：承接人选择新承接人并填写转派理由，系统校验新承接人存在且不为当前用户，更新任务承接人信息，为新承接人创建待办事项。
2. 派发人可执行**撤回**操作：填写撤回理由，系统校验任务状态为待承接且当前用户为派发人，任务状态更新为已撤回。
3. 承接人完成处理后提交审核，任务状态从处理中流转到待审核。
4. 审核拒绝则任务状态变为业务已拒绝，任务回到处理中状态，承接人可修改任务后重新提交审核。
5. 拆解完成是任务终态。当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成。

**业务规则：**

- 仅待承接状态的任务可被承接、拒绝、转派或撤回。
- 转派时不能转派给自己，新承接人必须存在且有效。
- 拒绝理由不能为空且长度不超过 512 字符。
- 仅待承接或处理中状态的任务可修改任务标题。
- 仅待审核状态的任务可执行业务审核。
- 审核通过后任务进入拆解阶段（流转到拆解中），审核拒绝后任务回到处理中状态，承接人修改后重新提交审核。
- 任务复用仅允许复用已拒绝或已撤回的任务，复用时恢复为待承接并清空原因。
- 需求完成约束：当需求下所有有效任务状态均为审核完成或拆解完成时，需求状态自动更新为已完成，需求状态更新不影响审核完成或拆解完成的任务。

**业务对象：** 任务状态（待承接/处理中/待审核/审核完成/拆解中/拆解完成/已拒绝/已撤回/业务已拒绝）、承接人信息、拒绝/转派/撤回理由、PRD 工作空间与会话

**业务界面：** 待办任务列表、任务详情与操作页面（承接/拒绝/转派/撤回按钮）、审核操作页面。无独立界面说明的存量功能由现有界面承载，本次不新增界面。

**完成标准：** 承接人可执行承接、拒绝、转派操作，派发人可执行撤回操作，任务状态正确流转（待承接→处理中→待审核→审核完成→拆解中→拆解完成/业务已拒绝）；审核流程正常执行，审核通过后任务进入拆解阶段；拆解完成是任务终态；所有任务审核完成或拆解完成时需求自动完成。

**涉及存量功能编码清单：** FUN202610122109340093477408769（任务流转与处理）、FUN202610122109327382592999425（任务承接状态管理）

### M03 技术功能点拆解

模块编号：M03。业务对象为功能点，管理目标为拆解、资产绑定和迭代进度统计，覆盖功能点从待拆解到已拆解的完整生命周期。

#### F06 功能点拆解与管理

> **变化类型：调整。** 存量功能侧重于模块→功能组→功能点的层级浏览和信息管理，以及业务功能信息的保存和回调管理。本次调整新增拆解状态管理（待拆解/已拆解）和迭代维度进度统计。

**业务流程：**

1. 承接人进入业务视图管理界面，通过域 ID 查询子系统下的模块列表，选择目标模块后查询功能组列表，再选择功能组查询功能点列表。
2. 承接人查看功能点详情：系统通过 RPC 调用获取功能点的完整信息（服务名称、URL、模块、功能组、方法签名、调用出度统计等），帮助承接人了解现有功能点的能力。
3. 承接人可更新功能点的名称、描述和业务流程实现说明：系统校验功能点 ID、名称、描述均为必填项，通过 RPC 调用 APAM 子系统执行异步更新；更新业务流程时检查是否存在进行中的 AI 分析记录，若存在则拒绝更新以防数据冲突。
4. 承接人完成 PRD 文档章节拆分后，系统自动或由用户手动触发保存业务功能信息到 MySQL 数据库和 Elasticsearch 索引，包含任务 ID、需求 ID、功能标题、功能内容等。
5. 功能点可绑定存量服务或函数资产：雪狼系统在立项审批完成后回调本平台，更新业务功能的立项信息和状态（绑定/变更/解绑）。
6. **本次新增**：承接人管理功能点拆解状态（待拆解→已拆解），完成功能点拆解并绑定资产后状态更新为已拆解。
7. **本次新增**：系统按迭代统计待拆解和已拆解的功能点数量，提供拆解进度可视化。任务审核通过后进入拆解阶段（审核完成→拆解中），所有关联功能点拆解完成后任务流转到拆解完成，拆解完成是任务终态，不再回退。

**业务规则：**

- 域 ID 为空时返回空列表；功能点不存在时返回空对象。
- 功能点 ID、名称、描述均为必填项，通过 RPC 调用 APAM 子系统执行异步更新。
- 更新业务流程时检查是否存在进行中的 AI 分析记录，若存在则拒绝更新以防数据冲突。
- ES 保存失败不影响 MySQL 主流程。
- 雪狼系统立项回调支持绑定、变更和解绑三种操作。
- **本次调整新增**：功能点拆解状态为待拆解或已拆解，完成拆解并绑定资产后状态更新为已拆解。

**业务对象：** 工作台泳道数据（待沟通需求、待接收任务、处理中任务、待审核任务、审核完成任务）、工作空间负载统计、会话列表
