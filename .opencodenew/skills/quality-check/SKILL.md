# 三域质检规范

## 通用质检纪律

### 质检范围

- 质检 = 机验 + 语义检：机验覆盖的格式问题以机验结果为准，机验通过后不再重复入报告；机验 `failures` 逐条记阻塞并判未收敛。
- 报告只追加、不改写历史轮次；问题只进质检报告，只提建议，不代修产物、不预写方案。

### 报告结构

三份报告通用骨架：

```markdown
## R{N}

**检查范围**：本轮检视的资料 / 功能模块 / TP 与批次

### 问题清单
| 问题编号 | 分级 | 条目 | 问题描述 | 证据锚点 | 建议 |
|---|---|---|---|---|---|
| Q-TP-R1-01 | 重大 | TP-004 | 颗粒度过细…… | prd1.md:15 => "……" | 并入 TP-002 |

### 对照表复检
| 问题编号 | 复检结果 | 核对说明 |
|---|---|---|

### 新增条目检查
……

### 待澄清问题
| 问题编号 | 问题与锚点 | 影响面 | 默认建议 |
|---|---|---|---|
| Q-M-R1-01 | …… | …… | …… |

### 待澄清资料缺口
| 问题编号 | 功能/测试点 | 缺失的维度/小类/关注点 | 证据锚点 | 默认建议 |
|---|---|---|---|---|
| Q-M-R1-D1 | …… | …… | …… | …… |

### 收敛判定
Y / N，列剩余阻塞与重大项
```

| 字段 | 要求 |
|---|---|
| 检查范围 | 本轮实际检视的资料或条目，分批时逐批列出 |
| 问题清单 | 每条问题附证据锚点；编号 `Q-M-R{N}-{seq}` / `Q-TP-R{N}-{seq}` / `Q-TC-R{N}-{seq}`；分级按【质检判据】；「条目」列写索引条目 / TP 编号 / TC 编号；概要失真按【概要质量判据】判定 |
| 对照表复检 | R2+ 填写 |
| 新增条目检查 | R2+ 填写 |
| 待澄清问题 | 仅 `qa-materials.md` 有；检什么与登记规则见【待澄清问题】 |
| 待澄清资料缺口 | 仅 `qa-materials.md` 有；一行一个缺口、一条一个问题，检什么与登记规则见【待澄清资料缺口】 |
| 收敛判定 | 阻塞与重大均为 0 才判 Y，两者不得降级放行；一般项不阻止收敛，遗留项记入 `state.md` 带过关口。判定语「阻塞 N / 重大 N / 一般 N；收敛判定 Y/N；一句理由」 |

### 质检判据

TP / TC 共用：

| # | 维度 | 判定要点 | 分级参考 |
|---|---|---|---|
| 1 | 数量守恒与覆盖 | 逐 TP 核直属 TC 数 M，口径按【机验前置】第 5 条；`用例展开重点` 项数 N 抽查展开充分性；正/反/边界分布合理；过半 TP 的 M 相同且与算法建议不符 → 判整批凑数 | `M<2` 或均一化→阻塞；偏少→重大 |
| 2 | 锚点真实性 | 抽验量与验真按【锚点口径】；原文没有的字段/功能却生成测试内容 → 阻塞 | 锚点不实或虚构对象→阻塞 |
| 3 | 臆造检测 | 按 `依据类型` 分路。`原文依据`：判定性内容无原文与澄清记录支撑即臆造，锚点写上限 25 测 26 合法、无 25 写 25 即臆造。`方法论补充` 只判四项：对象锚点不实；内容不在四份原文知识链或未按关注点发散；违反 workflow【依据类型二分与生成边界】静默生成禁令；借补充新增字段/功能 | 阻塞 |
| 4 | 排序 | TP 同功能相邻、功能级在前场景级收尾；TC 跟主 TP、段内正→反→边界；排序即优先级 | 段内乱序→一般；功能段被打断→重大 |
| 5 | 澄清/默认 | `澄清依据` 编号在 `state/clarifications.md` 存在且语义一致；`(默认)` 条目核默认建议是否正确应用、是否引入新风险 | 误用→阻塞；风险→重大 |
| 6 | 依据缺口决策一致性 | 按【待澄清资料缺口】的登记结果与 `state/clarifications.md` 处置决策，核对缺失维度/小类是否有对应 TP/TC；`依据类型` 逐条标注、不整批打包 | 缺失→重大 |

### 锚点口径

验真依据，产物覆盖 TP / TC / clarifications / resources-index：

| 原文类型 | 合法格式 |
|---|---|
| md/txt/csv | `文件名:起始行[-结束行] => "摘抄"` |
| docx | `文件名#章节标题 => "摘抄"` |
| xlsx | `文件名#Sheet名!单元格 => "摘抄"` |

1. 摘抄须为定位行 ≤50 字连续原文片段，超出以 `...` 截断；改写、缩合、补空格即判问题。
2. 摘抄含半角双引号、竖线、` => `，或单元格含竖线，即格式非法；多锚点用 ` ;; ` 分隔，分隔符须 ASCII `-`。
3. md 行区间须 `1 ≤ 起始 ≤ 结束 ≤ 总行数`；docx 标题须对应 Heading 段落；禁裸格式 `文件名:行号`。
4. 两类 `依据类型` 均带锚点逐条验真：`原文依据` 须支撑判定性内容，`方法论补充` 只须证明对象在原文存在。
5. 验真由机验 `verify_citation.py` 统一完成，见【机验前置】。

### 机验前置

按 `verify_citation.py` 行为：

1. **锚点**：按【锚点口径】；归一空白后子串比对，截断式按前缀匹配。`--index` 验索引锚点行，`--tp`、`--tc` 验清单「出处锚点」列。
2. **表格**：缺列、文件缺失或为空 → `fatal`；竖线不闭合的行被跳过、首表外数据行不可见 → warnings。
3. **值域与关联**：`类型` / `测试维度` / `所属小类` / `测试方法` / `依据类型` 逐行校验，白名单依次取 `TP_DIMENSIONS`、`TC_METHODS`、`BASIS_TYPES`，`所属小类` 单值；维度组合以 `test-knowledge-canon`《测试维度定义》「一、大类与测试维度总览」「二、测试维度明细」为准；`关联TP` 与 `关联业务功能` 须逐字一致；编号格式合法。
4. **澄清依据**：` ;; ` 分隔逐段校验 `C-\d+`，可带 `(默认)`，须存在于 `state/clarifications.md`；整格 `-` 或空为无澄清。
5. **数量守恒**：`--tp` `--tc` 同参时逐 TP 统计直属 TC 数 M，`M<2` 判 failures，`M=0` 由覆盖缺口 warning 承载、书面理由记 `state.md`；`依据类型` ∈ {原文依据, 方法论补充}，空或非法判 failures，两类均要求 `出处锚点` 非空且验真。

退出码 0 无失败、1 有失败、2 用法或致命错误，payload 含 `fatal_messages`。

人工核对项：排序分段、编号无跳号、命名词法、`用例类型` 五值、标题词法与一次判定、` ;; ` 与 `<br>` 范围、`用例展开重点` 项数 N、`关联业务功能` 写法、概要规范、报告章节格式。

## 资料质检

对索引逐条对照检查项，产出汇入 R1 报告：索引与概要类问题进「问题清单」，歧义点进「待澄清问题」，依据缺口进「待澄清资料缺口」。

### 机验执行

用 `--index`，不带 `--out`：

```bash
python3 SKILLS_ROOT/quality-check/scripts/verify_citation.py --docs <根>/project-docs --docs <会话>/user-input --index <会话>/scope/resources-index.md
```

机验通过后按【检查项】语义检视，原文按锚点定位片段核对。

### 检查项

| # | 检查项 | 判定 | 分级 |
|---|---|---|---|
| 1 | 索引完整性 | 选中功能相关章节、表格、规则段落未被收录，或逐节收录被合并成一条 | 阻塞 |
| 2 | 索引准确性 | 锚点位置与章节不符、行区间越界 | 阻塞 |
| 3 | 概要失真 | 概要与原文语义不一致 | 重大 |
| 4 | 范围覆盖 | 选中功能内容无法通过索引检索到 | 阻塞 |
| 5 | docx/xlsx 锚点可靠性 | 无 Heading 结构、无可用 Sheet，无法建立可靠锚点时另开澄清 | 阻塞 |
| 6 | 资料内部矛盾 | 不同资料对同一事项描述冲突，记问题并开澄清 | 重大 |
| 7 | 索引冗余 | 与圈定范围明显无关的条目 | 一般 |
| 8 | 待澄清资料缺口 | 知识库要测的维度/小类/关注点资料未描述且未登记 | 一般 |

### 概要质量判据

- 不精读原文即可判断该节是否值得打开。
- 实体齐全：角色、对象、状态字段名逐个列出，不得以行数概括。
- 数字阈值保留；异常分支点出。
- 做不到则摘引 ≤40 字原文短语。
- 臆造即问题；拿不准标「需核对」走澄清。

### 待澄清问题

- 检什么：业务规则缺失、资料矛盾、术语多义、docx/xlsx 无法建立锚点、原文检索定位失败。
- 怎么登记：一行一个歧义点，默认建议须可执行、可直接转断言口径；列定义见【报告结构】。

### 待澄清资料缺口

- 检什么：按 `test-knowledge-canon` 知识清单所引四份原文反查资料——资料只写了某个功能或对象、没写知识链要求测的测试维度/小类/关注点，这类「知识库要测、资料没描述」的内容登记为缺口；结合对资料的理解可一并列出测试点疑似缺失的其他待测项。测试维度/小类/关注点已有描述但不明确、有歧义的，不在此列，走「待澄清问题」。
- 怎么登记：按测试点聚合，一个测试点登记一条、编号 `Q-M-R{N}-D{seq}`；功能/测试点列写 功能编号+测试维度+所属小类；缺口描述列全该测试点的全部缺失项，逐项写明缺少的维度/小类/关注点，附对象锚点。不跨测试点合并，避免单题过长难决策。
- 默认建议：能给出可直接采用的推荐取值的，写具体推荐取值；给不出推荐取值的固定为「静默生成：依据四份原文知识链推导该维度/小类/关注点的测试内容，仅生成宽泛表述，不含具体取值」。
- 定性：这是资料描述缺口，不判资料不合格、不阻塞收敛，供关口 2 决策「静默生成 / 补充资料」；列定义见【报告结构】。

## 测试点质检

与【质检判据】并用。

### 机验执行

用 `--tp`，不带 `--out`：

```bash
python3 SKILLS_ROOT/quality-check/scripts/verify_citation.py --docs <根>/project-docs --docs <会话>/user-input --tp <会话>/output/tp/test-point-table.md --clar <会话>/state/clarifications.md
```

通过后进入语义检视。

| 维度 | 判定要点 | 分级参考 |
|---|---|---|
| 颗粒度 | 基准按 `test-point-workflow`【方法链】第 5 步与《测试点生成指南》「四、测试点颗粒度控制」的 4.1 粒度判断标准；`用例展开重点` 项数 N 少于 PRD 客观分支 → TP 过粗，拆 TP 而非补 TC；单条用例 → 过细；多条独立规则 → 过粗；查询项无 TC 且无豁免 → 展开不足 | 阻塞/重大 |
| 命名规范 | 风格漂移、结果词、处理逻辑、具体值、并列双结果谓词、验证词重复，命中即判错 | 重大 |
| 功能级/场景级互斥 | 场景级重复功能级细节；同一逻辑两处出现 | 重大 |
| 全集覆盖 | 六查：正向/反常/规则遗漏/臆造/过细/过粗，臆造按【质检判据】维度 3 分路；圈定小类每个至少 1 条 TP；选型圈定组合不落盘 | 缺失→阻塞；漏补→重大 |
| 范围一致性 | 选中功能的每个叶子功能点均有 TP，无范围外条目，场景级挂载正确 | 缺失→阻塞 |

## 测试用例质检

与【质检判据】并用。

### 机验执行

用 `--tp` 与 `--tc` 同参，不带 `--out`；`--tp` 供 TC 交叉校验，不重判 TP 自身：

```bash
python3 SKILLS_ROOT/quality-check/scripts/verify_citation.py --docs <根>/project-docs --docs <会话>/user-input --tp <会话>/output/tp/test-point-table.md --tc <会话>/output/tc/test-case-table.md --clar <会话>/state/clarifications.md
```

通过后进入语义检视。

| 维度 | 判定要点 | 分级参考 |
|---|---|---|
| 展开完整性 | 字段校验类核「字段清单 × 约束矩阵」，含方法论补充约束、空值逐字段遍历；边界值按《通用测试方法论》「五、测试方法详解」5.1.2「边界值分析」六点法；经验场景形态零覆盖 → 问题 | 矩阵/边界点/清单缺项→重大 |
| 方法适配 | TP 形态 ↔ `测试方法`；状态流转类全非状态迁移、组合类全无决策表 → 提示 | 错配→一般 |
| 硬凑检测 | 同值改名、伪边界、拆一为多、按 TP 均摊条数、空壳充数、方法论补充复制改名 | 均摊/空壳→阻塞；其余→重大 |
| 字段质量 | 逐列核标题、测试数据、操作步骤、预期结果；已明确的角色/状态/字段/文案泛化判错 | 重大 |
| 用例重复 | 两条 TC 同 TP + 同数据 + 同步骤 + 同预期 | 重大 |
