# 测试知识库原文索引

本 skill 只作四份 `references/` 原文的索引与阅读指引，不复述原文，也不登记流程、判据与格式契约。原文为不可变知识层，一字不改。

路径锚点：`SKILLS_ROOT/test-knowledge-canon/references/`；表内 `references/...` 均相对本 skill 根。

## 一、知识清单

| 编号 | 文件 | 解决什么问题 |
|---|---|---|
| ① | `references/1 通用测试方法论.md` | 用什么方法测 |
| ② | `references/2 测试维度定义.md` | 从哪些维度测 |
| ③ | `references/3 通用测试规则.md` | 每个维度具体测什么 |
| ④ | `references/4 测试点生成指南.md` | 测试点怎么拆、怎么命名、怎么从需求推导 |

## 二、章节索引

### ① 通用测试方法论

- `四、测试技术分类`：静态/动态与黑盒/白盒/灰盒技术分类。
- `五、测试方法详解`、`六、测试级别与阶段`、`七、方法选型决策指南`：方法、级别与选型。

### ② 测试维度定义

三级骨架：大类 → 测试维度 → 小类。

- `一、大类与测试维度总览`、`二、测试维度明细`：维度总览与各小类明细。
- `三、维度选型指南（按银行业务系统类型推断）`、`四、维度组合示例（银行业务场景）`：场景到维度组合的映射与示例。

### ③ 通用测试规则

按「大类 → 测试维度 → 小类 → 关注点」四级展开，命名与 ② 一致。

- `一、功能测试`、`二、非功能测试`：各维度下的具体测试项。
- `附录：与《测试维度定义》的对应关系`：章节到 ② 维度 / 小类的映射。

### ④ 测试点生成指南

测试点的概念、拆分、命名、颗粒度、模板库与生成流程。

- `一、核心概念定义`、`二、功能点拆分规则`、`三、测试点命名规范`、`四、测试点颗粒度控制`：概念与写法。
- `五、典型测试点模板库`、`六、测试点生成工作流程`：模板与自检流程。
- `七、与两份规则文档（及用户业务规则）的配合关系`：完整知识链与映射路径。

## 三、原文知识链与阅读顺序

阅读顺序：② 定骨架 → ③ 取关注点 → ④ 写成测试点 → ① 选方法；用户业务规则为补充输入，位于 ③ 与 ④ 之间。

1. **② 定骨架**：先按 §三 判断场景类型、定维度组合，再按 §二 明细表逐类展开（② 文末「使用建议」）。
2. **③ 取关注点**：按附录对应关系把小类映射到对应章节取详细测试项。
3. **④ 写成测试点**：按 §二 至 §六 拆分、命名、控颗粒度、套模板库、自检。
4. **① 选方法**：② 文末「使用建议」点名 ① 为方法依据，按 ①§七 选取用例设计方法。

只说明知识先后，不规定执行时序。

## 四、维护规则

1. 四份原文一字不改；规则冲突经用户裁决需修订时，按裁决结论改动对应片段，整体替换文件仍由用户决定。
2. 新增知识原文文件时，在「知识清单」表登记一行；删除条目前先确认无引用。
