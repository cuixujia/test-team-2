# 测试点生成与清单规范

功能点拆分、命名、颗粒度、模板库与生成流程按 `test-knowledge-canon`【段级索引】行段执行，取段范围由委派方给定。本文只承载产物清单规则与原文未覆盖的生成细则。

## 生成规则

### 依据类型与生成红线

- `原文依据`：验证方向与判定内容由 `出处锚点` 或澄清答复直接推导。
- `方法论补充`：资料缺某维度/小类/关注点而知识链有 → 按该关注点发散补 TP。
- 五条红线，违反即虚构，QA 判阻塞：
  1. 验证对象须有原文锚点；原文没有的字段、功能、状态、角色，不生成 TP。
  2. 不补造业务规则与提示文案，不把未描述内容写成已描述。
  3. 无依据支撑的内容静默生成，只写宽泛表述，不写死具体值、阈值、枚举值、文案。
  4. 具体取值须以澄清答复为依据，`澄清依据` 标 C 编号，无则写 `-`。
  5. 两类 TP 均须带 `出处锚点`。

### 条目与命名细则

- 查询/筛选：并列且规则相同的查询项合为一条 TP，`用例展开重点` 逐项点名；PRD 明文规定不同结果的须拆。
- 描述不清：并列条件规则未明 → 按同一目标合一条，不自造规则。
- 并列双结果：同一处理逻辑可合，PRD 规定不同规则则拆。
- 「验证XX功能」式：直属 TC 承载两类及以上判定维度才合规，否则拆分；PRD 原词照抄不受此限。

### 排序规则

- 同 `关联业务功能` 的 TP 相邻，段序按 scope 选中项，不许 F01 → F02 → F01。
- 段内先功能级，按正向 → 核心逻辑与状态 → 异常处理 → 边界与数据校验 → 其他排列，再以场景级收尾。
- 场景级按流程起点或主承载功能归段，归属不明查主件说明。排序由 QA 判定，生成方不回读重排。

## 清单结构

### 落盘模板

文件骨架：

```markdown
# 测试点清单

| 编号 | 关联业务功能 | 测试点名称 | 类型 | 测试维度 | 所属小类 | 用例展开重点 | 依据类型 | 澄清依据 | 出处锚点 |
|---|---|---|---|---|---|---|---|---|---|
| TP-001 | F01 需求新增 | 验证新增界面展示正确性 | 功能级 | 基础功能 | 功能正确性 | UI：页面布局 ;; 元素可见性 | 原文依据 | - | prd1.md:5 => "系统支持新增个人客户与对公客户" |
| TP-002 | F01 需求新增 | 验证正常输入新增功能正确性 | 功能级 | 基础功能 | 功能正确性 | 正向主流程 ;; 数据落库 ;; 状态变更 | 原文依据 | C-01 | prd1.md:15 => "保存成功后状态置为待审核" |
| TP-003 | F01 需求新增 | 验证新增输入域长度与字符约束 | 功能级 | 基础功能 | 字段校验 | 姓名最大长度 ;; 姓名特殊字符与空格 ;; 年龄数值精度 | 方法论补充 | - | prd1.md:8 => "表单字段：姓名、年龄" |
| TP-004 | F01 需求新增 | 验证新增-审核-推送完整流程 | 场景级 | 业务流程 | 主流程 | 基本流正向贯通 ;; 环节失败备选流 | 原文依据 | C-02(默认) | prd1.md:20 => "审核通过后触发推送" |
```

### 字段要求

| 字段 | 要求 |
|---|---|
| 编号 | `TP-001` 起三位递增，永久稳定、不得复用。删除或插入条目不改其他编号，删除留空号；新增取当前最大号加一，不回填空号。机验 `TP-\d+` |
| 关联业务功能 | scope 选中功能，`F01 需求新增` 格式；禁自创模块词；TC 侧逐字一致 |
| 测试点名称 | 短语级 ≤30 字，PRD 叫法照抄；禁结果词、处理逻辑、具体值、并列双结果；`验证` 仅一次 |
| 类型 | 仅 `功能级` / `场景级`；单功能点为功能级，跨功能点链路为场景级 |
| 测试维度 | 单值，取《测试维度定义》「一、大类与测试维度总览」十枚举之一 |
| 所属小类 | 单值，须属于所选维度下《测试维度定义》「二、测试维度明细」合法小类；圈定小类每个至少 1 条 TP，人工对表，缺失阻塞 |
| 用例展开重点 | 2~3 项以上，` ;; ` 分隔，每项一个可独立判定分支；按 PRD 客观分支计数；字段校验另计《测试维度定义》1.2 字段校验关注点与《通用测试规则》1.2 六大固定测试场景、输入域联动；来源为《测试点生成指南》模板库右列 + 《通用测试规则》关注点；元描述不计入 N |
| 依据类型 | 仅 `原文依据` / `方法论补充`，单值非空 |
| 澄清依据 | 无写 `-`；有写 `C-编号` 或 `C-编号(默认)`，多值 ` ;; `，编号须在 `state/clarifications.md` 存在 |
| 出处锚点 | 至少 1 条，一般 1~3 条 |
| 通用书写 | 换行 `<br>`，禁真实换行；多值项：锚点、澄清依据、用例展开重点 |
