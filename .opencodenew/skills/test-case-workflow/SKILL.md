# 测试用例生成与清单规范

## 生成规则

### 依据类型与生成红线

- `原文依据`：判定性内容由 `出处锚点` 或澄清答复推导还原，含数值、阈值、枚举值、状态名、文案。
- `方法论补充`：资料未描述该测试维度、所属小类或关注点，按知识库既定测试维度发散补用例，用来提高覆盖率。
- 五条红线，违反即虚构，QA 判阻塞：
  1. 验证对象须有原文对象锚点；原文没有的字段、功能、状态、角色，不得生成对应用例。
  2. 不得补造流程、权限、结果、状态流转等业务规则与提示文案；资料未描述的内容不得虚构为已描述。
  3. 无具体依据支撑的 `测试数据` / `预期结果` 只写宽泛表述：最大值、最小值、超长、特殊字符、空格、脚本，不写死具体值；预期结果写语义级。
  4. 具体取值须以澄清答复为依据，`澄清依据` 标对应 C 编号；无澄清依据写 `-`。
  5. 两类 TC 都必须带 `出处锚点`；同一 TP 下两类用例可并存，但 `依据类型` 须逐条标注，不按 TP 整批打包。

### 展开数量守恒

- 输入域形态按「字段清单 × 约束矩阵」逐字段落用例，逐项覆盖。约束矩阵取原文已给约束与测试维度发散约束之和，发散约束展开的用例落 `方法论补充`。
- 空值遍历逐字段一条，每条只留空一个必填字段、其余填合法值；每个输入域表单必补 1 条全字段空值用例，字段校验类计数相应 +1。
- 边界值用例须逐点落到具体取值，精度类对称处理，禁「超出长度上限」式单侧笼统。「封顶」只作用于 TP 拆分方向，不构成 TC 数量上限。
- 经验场景清单按需求形态命中才展开，以补充用例承载，方法主选型不变，不机械全覆盖。
- `用例展开重点` 的项数 N 按 TP 形态核算，仅作展开充分性建议，不是机验下限。人工复核发现展开明显不足时，回到该 TP 的 `用例展开重点` 逐项补齐，不得靠补空壳、复制改名绕过。

| TP 形态 | N 的核算建议 | 示例 |
|---|---|---|
| 字段校验 / 接口参数校验 | 字段数 × 约束类型数，含原文已给与发散约束；空值逐字段各一条 + 全字段空值 1 条 | 6 个任务字段，必填、长度、SSO 有效性 → 11 条 |
| 状态流转 | 合法边逐条 + 非法扭转 ≥1 | 7 条合法边 → ≥8 条 |
| 查询/筛选 | 查询项逐项 + 组合筛选 1 + 空结果 1 | 状态、领域、时间 → ≥5 条 |
| 权限控制 | 角色 × 操作矩阵的有效格逐格 + 越权反向 ≥1 | 承接人、派发人 × 承接、撤回 → ≥5 条 |
| 场景级主流程 | 基本流 1 + 各备选流逐条 | 3 个备选流 → ≥4 条 |
| 可靠性与稳定性容错 | 外部依赖逐项 + 开关分支逐项 | 5 个外部系统 → ≥5 条 |
| 数据一致性 / 数据正确性 | 各对比基准、一致性方向逐项 | 订单、库存、流水三方 → ≥3 条 |
| 其他形态 | 展开重点列点名的项数 | — |

- 条数来自客观计数：禁止为凑数复制改名、伪边界、同值换装，禁止仅以序号或「验证 1 / 验证 2」式区分标题。

### 排序规则

- 主 TP 排在哪，它的用例就排在哪；同一业务功能、同一条 TP 的用例各自排在一起，中间不插别的 TP。
- 不许按用例类型或测试方法把整张表重新排序；场景级 TP 的用例也不集中挪到清单最后。
- 一条 TP 内部的用例按 正向 → 反向/异常 → 边界 排。排序须人工逐行核对，不进机验。

## 用例四列

判定性内容按 `依据类型` 分路，字段名、状态名、角色名一律照抄原文术语；提示文案资料给了照抄锚点原文，没给写语义级预期，禁杜撰；步骤顺序、前置账号与环境、构造方法属测试设计自由度，涉及的状态名、角色名、字段名须与资料术语一致。资料已明确的叫法不得泛化，资料未给才允许语义级表述。

| 列 | 要求 |
|---|---|
| 标题 | 一律「验证 + 场景 + 预期落点」；一个标题只承载一次判定，预期结果可含多个观察点但须同属一次判定；短语级 ≤30 字，对象词沿用主 TP 名称的 PRD 叫法；同 TP 内以差异点区分，不重名；禁承载具体数据字面值，具体值写 `测试数据` 列，场景语义词如 上边界、超长、空值、缺省 允许 |
| 测试数据 | 赋值式 `字段=值`，多值以「；」分隔，日期区间写「起 至 止」，构造方法标「构造：…」，多记录逐条枚举或给生成规则；或状态描述式，按自然语句书写并须含具体数值；同一承载形态内符号一致；给具体值或可执行构造方法，禁「系统正常」「适当数据」类可随意替代的表述 |
| 操作步骤 | 动词开头、编号分步，不含「等一下」「适当输入」类歧义词；业务等待例外：等待定时任务触发、状态扭转、异步回调、消息到达等系统行为且后续步骤含可判定观察点的，写「等待/触发」合规；准备产物被后续引用或观察的作前置编号步骤，纯环境置备写 `前置条件` 列 |
| 预期结果 | 落到可观察物，可直接判 pass/fail：数据值/一致性、界面元素状态、提示文案、状态变更、消息推送内容任一；一致性判定必须点名对比基准，如 源系统、前端展示、数据库、导出文件、源平台；错误提示指向具体字段与原因 |

## 清单结构

文件骨架：

```markdown
# 测试用例清单

| 编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 测试方法 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 依据类型 | 澄清依据 | 出处锚点 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | F01 需求新增 | TP-002 验证正常输入新增功能正确性 | 验证全部必填合法输入新增成功 | 正向 | 等价类+边界值 | 已登录且有新增入口 | 客户名称=张三；证件号=110101199001011234 | 1.进入新增页<br>2.填写全部必填项<br>3.保存 | 保存成功；列表出现该记录；状态=待审核 | 原文依据 | - | prd1.md:15 => "保存成功后状态置为待审核" |
| TC-002 | F01 需求新增 | TP-002 验证正常输入新增功能正确性 | 验证超限客户名称创建被拦截 | 反向 | 等价类+边界值 | 已登录且有新增入口 | 客户名称=51个字符 | 1.进入新增页<br>2.名称填51字符<br>3.填写其余必填项<br>4.保存 | 拦截并提示名称超长；不落库 | 原文依据 | C-01 | prd1.md:12 => "客户名称长度不超过50个字符" |
| TC-003 | F01 需求新增 | TP-003 验证新增输入域长度与字符约束 | 验证姓名特殊字符与空格输入被拦截 | 反向 | 等价类+边界值 | 已登录且有新增入口 | 姓名=含特殊字符与首尾空格的值 | 1.进入新增页<br>2.姓名填入特殊字符值<br>3.填写其余必填项<br>4.保存 | 拦截并提示字符不合规；不落库 | 方法论补充 | - | prd1.md:8 => "表单字段：姓名、年龄" |
| TC-004 | F01 需求新增 | TP-003 验证新增输入域长度与字符约束 | 验证年龄小数精度输入被拦截 | 边界 | 等价类+边界值 | 已登录且有新增入口 | 年龄=超出规定小数位数的值 | 1.进入新增页<br>2.年龄填入超精度值<br>3.填写其余必填项<br>4.保存 | 拦截并提示精度不合规；不落库 | 方法论补充 | - | prd1.md:8 => "表单字段：姓名、年龄" |
```

| 字段 | 要求 |
|---|---|
| 编号 | `TC-001` 三位数字起步；重排后必须重编号，连续无跳号，与 TP 对称；机验正则 `TC-\d+` |
| 关联业务功能 | 主 TP 所属业务功能，逐字等于其主 TP 的 `关联业务功能`；机验直接拦截主从挂错簇 |
| 关联TP | 第一个空格分隔编号段与名称段，如 `TP-002 验证正常输入新增功能正确性`。编号段恰好一个主 TP，格式 `TP-\d+` 且必须存在于 TP 清单；名称段逐字取自该 TP 的 `测试点名称`，不得缩写、改写、同义替换。一 TC = 一 TP，不设多挂靠，「顺带验证」不构成理由，跨功能点链路由场景级 TP 承载；TP 侧名称变更时名称段同步更新 |
| 用例名称 | 单值短语；同 TP 内以差异点区分，不重名 |
| 用例类型 | 仅 `正向` / `反向` / `边界` / `场景` / `异常`，纯白名单，保证统计不失真 |
| 测试方法 | 单值，六枚举：`等价类+边界值` / `决策表` / `状态迁移` / `场景法` / `正交实验` / `错误推测`；因果图按决策表口径落值。一条 TP 的展开通常同方法，跨方法时按用例各自标注 |
| 前置条件 | 账号、环境、数据就绪态；纯环境置备无中间观察的写本列，不进操作步骤；术语须与资料一致 |
| 测试数据 | 赋值式或状态描述式；给具体值或可执行构造方法 |
| 操作步骤 | 动词开头、编号分步 |
| 预期结果 | 落到可观察物，可直接判 pass/fail |
| 依据类型 | 仅 `原文依据` / `方法论补充`，单值非空 |
| 澄清依据 | 无写 `-`；有写 `C-编号` 或 `C-编号(默认)`，多值 ` ;; ` 分隔；编号必须存在于 `state/clarifications.md`；无澄清依据的方法论补充用例写 `-`，有澄清答复的具体值标对应 C 编号 |
| 出处锚点 | 引用与该用例最直接相关的原文位置，通常继承关联 TP 的锚点，也可按需补充 |
| 通用书写 | 表头须含全部 13 列；单元格内换行用 `<br>`，禁止真实换行，`<br>` 仅限操作步骤列且步骤间以 `<br>` 分隔；多值项用 ` ;; ` 分隔，多值项为锚点、澄清依据 |
