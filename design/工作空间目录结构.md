# AI 运行时工作空间目录结构（v1，与 design-v1.md §4 对齐）

## 工作空间根

优先 `/file/`；运行环境无 `/file/` 时，在本团队仓库根创建 `runtime-file/` 沿用同一结构。测试专家在会话启动时把实际根写入 state.md。

## 目录结构

```text
<工作空间根>/
├── project-docs/                        # 用户的项目文档（BRD、PRD 等）——只读
│   ├── brd1.md
│   └── prd1.md
│
└── session-<项目id>-<时间戳>/           # 一个会话 = 一次完整的"资料进来、用例出去"
    ├── user-input/                      # 用户随会话上传的补充资料（只读）
    │
    ├── scope/                           # 【地基】范围与检索入口
    │   ├── scope.md                     # 范围确认单
    │   └── resources-index.md           # 内容索引
    │
    ├── state/                           # 【状态】流程与台账
    │   ├── state.md                     # 进度看板 + 结论摘要 + 实施日志
    │   ├── clarifications.md            # 澄清台账
    │   └── repair-log.md                # 修复对照表
    │
    └── output/                          # 【成品与检验记录】
        ├── tp/
        │   └── list.md                  # 测试点清单
        ├── tc/
        │   └── list.md                  # 测试用例清单
        └── reports/                     # 质检报告（QA 唯一可写区）
            ├── qa-materials.md          # 资料索引质检（含"待澄清问题"章节）
            ├── qa-tp.md                 # 测试点质检
            └── qa-tc.md                # 测试用例质检
```

## 文件格式契约

模板的唯一权威在各 skill；此处只定字段清单（列名与脚本机验绑定，不得改名）。

### scope.md（测试专家写）
表格列：`| 业务功能 | 是否选中 | 识别依据锚点 |`。是否选中取值：`是 / 否`。

### resources-index.md（测试专家写）
按资料分节（`## 文件名`），每节表格列：`| 章节 | 锚点 | 概要 |`。概要 ≤50 字。

### state.md（测试专家写）
固定小节：`当前阶段`、`当前轮次`、`待用户事项`、`各阶段结论摘要`、`实施日志`。实施日志记录每轮 QA 后对 reports/ 之外文件的抽查结果。

### clarifications.md（测试专家写）
表格列：`| 编号 | 来源 | 问题 | 影响面 | 默认建议 | 答复 | 状态 |`。
编号 `C-01` 递增；来源填产生阶段（如 `材料质检R1`）；答复未收到填 `-`；状态取值：`待答复 / 已答复 / 默认生效`；其余取值规则见补充《产物格式规范》§四。

### repair-log.md（测试专家写）
按轮分节（`## 材料R1`、`## TP-R2`、`## TC-R1`），每节表格列：`| 问题编号 | 修复动作 | 牵动条目 |`。问题编号与 QA 报告中一一对应。

### tp/list.md（测试专家写，6 列）
`| 编号 | 关联业务功能 | 测试点名称 | 类型 | 澄清依据 | 出处锚点 |`
编号 `TP-001` 递增；类型：`功能级 / 场景级`；澄清依据：`-`、`C-01` 或 `C-01(默认)`；出处锚点可多条，` ;; ` 分隔；取值规则与关联业务功能取法见补充《产物格式规范》§二。

### tc/list.md（测试专家写，11 列）
`| 编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点 |`
编号 `TC-001` 递增；关联TP 单个 TP 编号；用例类型：`正向 / 反向 / 边界 / 场景 / 异常`；不设优先级字段，排序即优先级（业务功能簇内按测试点序、簇内同法则，见知识④§六步骤 6 + 裁决六 B2）。

### qa-materials.md / qa-tp.md / qa-tc.md（QA 写，唯一可写区）
每轮一个小节 `## R{n}`，内含：检查范围与批次、问题表（`| 问题编号 | 分级 | 位置或条目 | 问题描述 | 证据锚点 | 建议 |`）、R2+ 的对照表复检结果、新增条目检查、收敛判定。问题编号规则：`Q-M-R{n}-{seq}` / `Q-TP-R{n}-{seq}` / `Q-TC-R{n}-{seq}`。分级取值：`阻塞 / 重大 / 一般`。qa-materials.md 的 R1 另含"待澄清问题"章节（每条必附默认建议）。报告只追加，历史轮次不改写。

## 出处锚点格式（唯一口径，与 design-v1.md §5 一致）

- md/txt/csv：`文件名:起始行[-结束行] => "摘抄"`
- docx：`文件名#章节标题 => "摘抄"`（不转 md，机验现场抽取）
- xlsx：`文件名#Sheet名!单元格 => "摘抄"`
- 摘抄 ≤50 字（不含结尾截断符），超出截断并以 `...` 结尾；摘抄内禁止半角双引号；多条锚点用 ` ;; ` 分隔
