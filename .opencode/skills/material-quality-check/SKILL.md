# 资料质检（QA · 阶段 2）

## 方法来源

质检方法采用静态评审的检查表思想：见 skill `test-knowledge` 的 `references/1 通用测试方法论.md` §4.1（检查表/走查技术——按固定检查项清单逐项核对、每项给出客观判定）。本 skill 只登记检查项与产物格式，方法不复述。

## 输入

经理委派必须提供：工作空间根与会话目录、scope/scope.md（选中项）、scope/resources-index.md、全部原文目录（project-docs/ 与 user-input/）、round 编号；R2+ 轮另有 state/repair-log.md 对应小节名（`## 材料R{n}`）。

## R1 全量检查（先通读，凡圈定范围内的内容均须对照）

通读全部资料一次，然后按以下检查项逐项输出问题（每条给证据锚点）：

| # | 检查项 | 判定 | 分级 |
|---|--------|------|------|
| 1 | 索引完整性 | 圈定范围相关的原文内容（章节、表格、规则段落）未被索引收录 → 问题 | 阻塞 |
| 2 | 索引准确性 | 索引条目锚点指向的位置与章节不符、行区间越界 | 阻塞 |
| 3 | 概要失真 | 概要与原文语义不一致（≤50 字概要扭曲了原意） | 重大 |
| 4 | 范围覆盖 | scope 选中功能的相关内容无法通过索引检索到 | 阻塞 |
| 5 | docx/xlsx 锚点可靠性 | docx 无 Heading 章节结构、xlsx 无可用 Sheet/单元格 → 记问题；无法建立可靠锚点的，另开澄清问题 | 阻塞 |
| 6 | 资料内部矛盾 | 不同资料间对同一事项描述冲突 → 记问题并开澄清 | 重大 |
| 7 | 索引冗余 | 与圈定范围明显无关的索引条目 | 一般 |

锚点抽验方法：md/txt/csv 直读原文比对行区间；docx/xlsx 用只读命令逐条抽验：

```
python3 .opencode/skills/citation-verify/scripts/inspect_anchor.py \
  --docs <根>/project-docs --docs <会话>/user-input --anchor '<锚点>'
```

## R1 第二产出：待澄清问题章节

从通读中提取所有影响 TP/TC 生成的歧义点，写入 qa-materials.md R1 的"待澄清问题"小节，每条必含四要素：

| 字段 | 要求 |
|---|---|
| 问题 | 一句话说清歧义，附着证据锚点 |
| 影响面 | 波及哪些功能/维度/可能的 TP |
| 默认建议 | 用户不答复时按此执行的可操作判定（必须有，不许空） |
| 来源 | 材料的锚点位置 |

产生澄清问题的典型情形：需求与设计描述冲突、关键规则缺失（如未定义边界值）、术语多义、docx/xlsx 无法建立锚点、原文检索定位失败。

## R2+ 增量复检

只做两件事：①逐条核 repair-log 对应小节的问题编号：已修复（给出核对锚点）/ 未修复 / 部分修复；②检查修复中新增或改动的索引条目。未触及的条目不重查。

## 收敛判定

本轮无阻塞级问题 → 判"收敛"；否则判"未收敛"并逐条列出剩余阻塞项。绝不因轮次压力把未修复的阻塞项降级放行。

## 报告格式（qa-materials.md，追加 `## R{N}` 小节，历史轮次不改写）

```markdown
## R{N}

**检查范围**：本轮实际通读/复检的资料与条目（分批时逐批列出）

### 问题清单
| 问题编号 | 分级 | 位置或条目 | 问题描述 | 证据锚点 | 建议 |
|---|---|---|---|---|---|
| Q-M-R1-01 | 阻塞 | resources-index.md §prd1.md | …… | prd1.md:12-15 => "……" | …… |

### 对照表复检（R2+）
| 问题编号 | 复检结果 | 核对说明 |
|---|---|---|

### 新增条目检查（R2+）
……

### 收敛判定
收敛 / 未收敛（剩余阻塞项：Q-…-…）
```

R1 轮在问题清单后另加 `### 待澄清问题`：`| 编号建议 | 问题（含锚点） | 影响面 | 默认建议 |`。澄清编号由经理后续编排（C-01 递增），QA 不占号。

## 纪律

只检不修；每个问题必须有证据锚点；禁止臆测原文；修复建议写给经理但不代做。
