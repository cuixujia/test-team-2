# 测试维度定义

> 本文档采用**大类 + 测试维度 + 小类**的三级结构，将测试维度归并为 **功能测试、非功能测试** 两个大类；覆盖规划按「大类 → 测试维度 → 小类」逐层展开，保证维度完整、不遗漏、不冗余。

---

## 一、大类与测试维度总览

| 大类        | 测试维度             | 小类       | 一句话说明                  |
| --------- | ---------------- | -------- | ---------------------- |
| **功能测试**  | **基础功能**         | 功能正确性    | 单个功能点是否正常可用            |
|           |                  | 字段校验     | 输入框/参数的格式与规则校验         |
|           |                  | 业务规则     | 计算公式、阈值、策略等规则逻辑        |
|           |                  | 异常与错误处理  | 异常输入、操作失败、错误提示         |
|           | **业务流程**         | 主流程      | 核心业务路径的端到端验证           |
|           |                  | 分支流程     | 各条件分支、兜底路径、异常处理分支、跳转逻辑 |
|           |                  | 状态流转     | 状态机、状态变更与扭转条件          |
|           |                  | 流程衔接与回退  | 跨环节衔接、撤销、回退、撤销后重走      |
|           | **界面与体验（UI/UX）** | 布局与适配    | 布局、分辨率、多端适配            |
|           |                  | 元素交互     | 按钮、弹窗、表单等控件行为          |
|           |                  | 文案与多语言   | 文案、提示、国际化              |
|           |                  | 视觉与易用性   | 视觉一致性、易用性              |
|           | **数据校验**         | 数据正确性    | 数据值、精度、展示是否准确          |
|           |                  | 数据一致性    | 跨模块、跨表、缓存与 DB 一致       |
|           |                  | 数据隔离     | 多用户/多租户间数据互不干扰         |
|           |                  | 数据存储与持久化 | 入库、落库、查询、导出            |
|           | **权限控制**         | 身份认证     | 登录、会话、凭证有效性            |
|           |                  | 功能权限     | 角色/身份对应的功能与操作范围        |
|           |                  | 数据权限     | 可见的数据范围（越权防护）          |
|           |                  | 操作审计     | 敏感操作的审批、留痕、防重放         |
|           |                  | 越权操作     | 水平/垂直越权与提权漏洞验证         |
|           | **接口 API 测试**    | 接口契约     | 接口入参出参与约定一致            |
|           |                  | 参数校验     | 接口入参的合法性与边界            |
|           |                  | 业务逻辑     | 接口背后的业务规则与数据处理         |
|           |                  | 异常处理     | 异常与依赖故障时的接口表现          |
| **非功能测试** | **性能**           | 响应速度     | 响应时间、吞吐量、资源占用          |
|           |                  | 并发正确性    | 并发场景下的数据正确性            |
|           | **安全**           | 防攻击      | 注入/XSS/CSRF 等攻击防护      |
|           |                  | 防泄露      | 信息泄露、加密、脱敏             |
|           | **兼容性与多端**       | 环境与设备    | 浏览器/OS/设备/网络兼容         |
|           |                  | 多端同步     | 多端数据同步与一致性             |
|           | **可靠性与稳定性**      | 故障恢复     | 容错、故障恢复、降级熔断           |
|           |                  | 健壮性      | 网络异常、资源耗尽、异常条件下的表现     |

## 二、测试维度明细

### 大类一：功能测试

#### 测试维度：基础功能

> 验证**单个功能点**是否正常工作。粒度最细，是其他所有测试维度的基石，几乎所有需求都需覆盖。

| 序号  | 小类          | 定义                                   | 关注点                                | 典型场景举例                             |
| --- | ----------- | ------------------------------------ | ---------------------------------- | ---------------------------------- |
| 1.1 | **功能正确性**   | 验证单个功能点的输入输出与预期一致，即"点一下能不能用"         | 正向主路径、输入输出、结果正确性、即时反馈              | 点击"发送验证码"按钮后手机收到短信，按钮进入倒计时         |
| 1.2 | **字段校验**    | 验证各输入域、表单字段的格式与规则校验，即"输入合不合法"        | 必填项、长度、格式（手机号/邮箱/身份证）、特殊字符、枚举值、默认值 | 手机号输入 10 位数字、字母、特殊符号时给出对应错误提示      |
| 1.3 | **业务规则**    | 验证需求中明确的业务规则被正确实现，即"规则算得对不对"         | 计算公式、阈值判断、优惠/折扣/积分、状态判定、定时/周期规则    | 满 300 减 50，验证 299/300/301 三档减免金额正确 |
| 1.4 | **异常与错误处理** | 验证异常输入、操作失败、依赖异常时系统的处理与提示，即"出错了怎么处理" | 空值/非法值、依赖不可用、操作失败、错误提示友好性、不影响其他功能  | 上传文件超过限制给出清晰提示；接口超时提示"网络异常，请重试"    |

#### 测试维度：业务流程

> 验证**多个功能点串联成的业务链路**是否完整、正确、可回退。粒度比基础功能更高一层。

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 2.1 | **主流程** | 验证核心业务路径的端到端正常流转，即"主路走得通不通" | 端到端链路、各环节状态与结果、关键节点产出 | 电商下单：选品→填地址→支付→生成订单→扣库存→发通知，全流程贯通 |
| 2.2 | **分支流程** | 验证各条件分支与替代路径，即"岔路走得对不对" | 条件分支、兜底路径、异常处理分支、跳转逻辑 | 支付时余额不足跳转到充值页；优惠券不可用提示并自动取消勾选 |
| 2.3 | **状态流转** | 验证对象状态机及各状态间扭转条件，即"状态变不变得对" | 状态枚举、扭转条件、非法扭转拦截、超时自动流转 | 订单状态 待支付→已支付→已发货→已完成，验证只能按序流转、不可跳步 |
| 2.4 | **流程衔接与回退** | 验证跨环节衔接、撤销、回退与重走，即"走错了能不能退回去" | 上一步/下一步、撤销、驳回、回退重填、跳转后返回、数据保留 | 支付失败后可返回修改地址；审批驳回后申请人可修改重新提交 |

#### 测试维度：界面与体验（UI/UX）

> 验证**用户可见的界面与整体使用体验**是否正确、友好、适配。纯后端/无界面的需求可不测。

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 3.1 | **布局与适配** | 验证页面布局与不同环境适配，即"换环境会不会乱" | 分辨率、多端适配、响应式、滚动、溢出、遮挡、弹窗层级 | 同一页面在 PC/手机/平板及不同分辨率下布局不乱、不溢出 |
| 3.2 | **元素交互** | 验证按钮、表单、弹窗等控件的交互行为，即"点上去反不反应" | 点击/长按/滑动、禁用态、加载态、弹窗确认、快捷键、焦点 | 必填项未填时提交按钮置灰；点击遮罩层弹窗关闭或保持 |
| 3.3 | **文案与多语言** | 验证界面文案与多语言支持，即"写的对不对、翻的准不准" | 文案正确性、错别字、占位符、多语言翻译、日期/货币/时区格式 | 切换中英文，验证所有按钮、提示、日期货币格式正确 |
| 3.4 | **视觉与易用性** | 验证视觉一致性与易用性，即"看起顺不顺眼、用起顺不顺手" | 风格统一、配色、图标、间距、加载骨架、空状态、易访问性 | 加载中显示骨架屏；列表为空显示空状态插画与引导文案 |

#### 测试维度：数据校验

> 验证**功能背后的数据**是否准确、一致、隔离、持久。涉及数据增删改查的需求必测。

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 4.1 | **数据正确性** | 验证数据的值、精度与展示是否准确，即"数据准不准" | 字段值、精度与舍入、默认值、统计汇总、前后端一致 | 订单金额与支付金额逐笔对账；报表汇总与明细合计一致 |
| 4.2 | **数据一致性** | 验证跨模块、跨表、多副本间的数据一致，即"数据串没串" | 主子表关联、缓存与 DB、读写分离、消息最终一致、数据迁移 | 改用户信息后订单页与用户中心同步更新；支付后库存/订单/流水三方一致 |
| 4.3 | **数据隔离** | 验证多用户/多租户间数据互不干扰，即"看不看得见别人的" | 水平越权、租户隔离、查询范围限制 | 用户 A 通过改 ID 访问用户 B 的订单应被拒绝 |
| 4.4 | **数据存储与持久化** | 验证数据的入库、落库、查询与导出，即"存得住、拿得出" | 落库正确性、查询检索、排序分页、导入导出、批量操作 | 批量导入 1 万条数据验证入库完整、导出文件内容与列表一致 |

#### 测试维度：权限控制

> 验证**谁能做什么、能看到什么、关键操作有没有留痕**。涉及用户身份、角色、数据的需求必测。

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 5.1 | **身份认证** | 验证登录与身份凭证的有效性，即"是不是本人" | 登录态、Token 过期、多点登录、单点登录、密码策略 | Token 过期后请求返回 401；退出后旧会话不可用 |
| 5.2 | **功能权限** | 验证不同角色的功能与操作范围，即"有没有权限操作" | RBAC/ABAC 权限矩阵、菜单/按钮可见性、垂直越权 | 普通用户访问管理员接口返回 403；无权限用户看不到导出按钮 |
| 5.3 | **数据权限** | 验证不同身份可见的数据范围，即"能不能看到该看的" | 数据范围、行级/列级权限、数据脱敏 | 部门 A 的员工看不到部门 B 的数据；手机号中间四位脱敏显示 |
| 5.4 | **操作审计** | 验证敏感操作的审批、留痕与防重放，即"关键操作有没有记录" | 审批流、二次确认、审计日志、敏感字段、防重放 | 删除操作需二次确认；管理员改配置后日志记录操作人/时间/内容 |
| 5.5 | **越权操作** | 验证水平/垂直越权与提权漏洞，即"越不越得过去" | 水平越权（同角色跨用户）、垂直越权（低权限调高权限接口）、提权、ID 可遍历、越权修改 | 用户 A 改 ID 访问用户 B 订单被拒绝；普通用户直接调管理员接口被拦截 |

#### 测试维度：接口 API 测试

> 验证**对外/对内接口**的功能正确性。粒度介于基础功能与业务流程之间，是银行系统（内部服务间、渠道对接、对外接口）的高频测试对象。

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 6.1 | **接口契约** | 验证接口入参出参与约定一致，即"契约对不对" | URL/方法、字段名/类型/必填、返回码、版本兼容 | 字段缺失/多余时返回约定错误码；新老版本接口兼容 |
| 6.2 | **参数校验** | 验证接口入参的合法性与边界，即"参数对不对" | 必填、类型、长度、格式、枚举、边界、特殊字符 | 金额为负、超长字符串、非法枚举值返回参数错误 |
| 6.3 | **业务逻辑** | 验证接口背后的业务规则与数据处理，即"逻辑算得对不对" | 业务规则、数据增删改查、状态变更、幂等 | 重复提交同一请求不重复入账；转账接口正确扣增双方余额 |
| 6.4 | **异常处理** | 验证异常与依赖故障时的接口表现，即"出错了怎么响应" | 依赖不可用、超时、限流、错误码、错误信息、降级 | 下游超时返回明确错误码；限流时返回 429 |

### 大类二：非功能测试

#### 测试维度：性能

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 7.1 | **响应速度** | 验证目标负载下的响应时间与资源利用，即"快不快" | 响应时间、吞吐量、并发数、资源占用、瓶颈 | 大促模拟 10 万并发下单，观测响应时间与错误率 |
| 7.2 | **并发正确性** | 验证并发场景下的数据正确性，即"并发对不对" | 竞态条件、超卖、重复扣款、脏读/幻读、幂等 | 100 人抢 10 件商品不超卖；超时重试支付不重复扣款 |

#### 测试维度：安全

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 8.1 | **防攻击** | 验证抵御常见攻击的能力，即"攻不攻得破" | 注入/XSS/CSRF、暴力破解、逻辑漏洞 | 登录框输入 `' OR 1=1--` 检测注入；抓包验证 Token 未明文传输 |
| 8.2 | **防泄露** | 验证敏感信息的保护能力，即"泄不泄得出去" | 信息泄露、加密传输与存储、数据脱敏、敏感日志 | 返回报文不含密码/密钥；日志中敏感字段脱敏 |

#### 测试维度：兼容性与多端

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 9.1 | **环境与设备** | 验证不同环境下的正常工作，即"换环境能不能用" | 浏览器/版本、OS、设备/分辨率、网络 | Chrome/Edge/Safari 布局功能一致；弱网下正常提示 |
| 9.2 | **多端同步** | 验证多端间数据同步与一致性，即"多端同不同步" | 手机/PC/平板数据同步、离线操作冲突 | 手机端与 PC 端购物车、待办事项同步一致 |

#### 测试维度：可靠性与稳定性

| 序号 | 小类 | 定义 | 关注点 | 典型场景举例 |
| --- | --- | --- | --- | --- |
| 10.1 | **故障恢复** | 验证故障与异常条件下的恢复能力，即"挂了能不能起来" | 容错、故障恢复、降级熔断、灾备 | 关掉一个服务节点自动 failover；数据库主库宕机自动切换 |
| 10.2 | **健壮性** | 验证异常与极端条件下的表现，即"出故障稳不稳" | 资源耗尽、内存泄漏、异常输入、长时间运行 | 磁盘写满/连接耗尽时优雅处理；7×24 运行无内存泄漏 |

## 三、维度选型指南（按银行业务系统类型推断）

> 以下从银行业常见后端系统类型出发，归纳**共性特质 → 应覆盖的维度组合**：先判断该需求属于哪类系统/哪类操作，再套用对应维度组合，避免遗漏。

| 银行业务场景 / 系统类型                        | 共性特质                | 应覆盖的大类、测试维度与小类                                                      | 说明                         |
| ------------------------------------ | ------------------- | ------------------------------------------------------------------- | -------------------------- |
| **增删改类操作**（如客户信息维护、参数配置、额度调整、后台管理）   | 界面有表单、有操作入口、涉及角色与审批 | **功能测试** → 基础功能 + 界面与体验（UI/UX） + 权限控制                               | 字段能校验、界面能操作、权限能控，是这类需求的三件套 |
| **多渠道接入**（手机银行、网上银行、柜面、POS 终端、ATM 等） | 同一套业务/数据，多个前端入口与设备  | **功能测试** → 基础功能 + 数据校验 + 界面与体验（UI/UX）                               | 各渠道功能一致、数据互通共享、界面分别适配      |
| **支付核心**（转账、支付、扣款、清算）                | 资金安全敏感、金额高、并发大      | **功能测试** → 基础功能 + 数据校验 + 接口 API 测试<br>**非功能测试** → 性能 + 安全 + 可靠性与稳定性 | 功能正确与资金数据一致是底线，性能/安全是重点    |
| **对账类**（交易对账、差错处理、清算对账）              | 核心是数据核对、金额统计、报表输出   | **功能测试** → 基础功能 + 数据校验                                              | 数据准确性、汇总统计、对账结果正确是核心       |
| **交易类**（开户、签约、认购、赎回、放款、还款）           | 有状态、有流程、涉及资金与凭证     | **功能测试** → 基础功能 + 业务流程 + 数据校验                                       | 链路要打通、状态要流转、金额要准确          |
| **权限与审批类**（角色管理、授权、审批流、审计）           | 控制谁能做什么、关键操作要留痕     | **功能测试** → 基础功能 + 权限控制（含越权操作）                                       | 功能权限与数据权限的矩阵验证是重点，越权必测     |
| **报表与查询类**（流水查询、余额查询、统计报表、导出）        | 数据展示、查询检索、汇总导出      | **功能测试** → 基础功能 + 数据校验 + 界面与体验（UI/UX）                               | 查询条件组合、数据正确性、展示与导出一致       |
| **批量/定时类**（日终批处理、利息计提、账单生成、批量代发）     | 定时触发、批量处理、结果落库      | **功能测试** → 基础功能 + 数据校验 + 接口 API 测试<br>**非功能测试** → 性能 + 可靠性与稳定性      | 批量数据准确性与处理效率、异常重试          |
| **对外接口类**（给第三方/渠道/合作方调用的接口）          | 契约明确、鉴权严格、安全性高      | **功能测试** → 基础功能 + 权限控制 + 数据校验 + 接口 API 测试<br>**非功能测试** → 性能 + 安全    | 接口契约、鉴权、数据正确与安全必测          |
