本 skill 只登记知识清单与原文阅读顺序；阶段划分、时序、加载时机见 `agent/test-expert.md` 对应阶段。依据供给与方法论补充边界见本文 §四；判别细则与格式契约内嵌于 `test-point-workflow`（切分判别细则、查询/筛选类专项、命名判据与词面筛检、全集自检六项）、`test-case-workflow`（TC 四列判据、展开数量守恒）、`citation-verify`（锚点口径、clarifications 表、清单表机器契约）。

## 二、原文阅读顺序

本 skill 只登记知识清单与原文阅读顺序；阶段划分、时序、加载时机见 `agent/test-expert.md` 对应阶段。方法链与阶段判据分别见 `test-point-workflow`「生成判据」与 `test-case-workflow`「生成判据」。

## 三、维护规则

1. 原文四份一字不改；调优只动三处内嵌判据段，或由用户决定整体替换原文。
2. 新增知识原文文件时，在「一、知识清单」表登记一行；删除条目前先检查无 skill 引用。团队细则类内容一律内嵌各 workflow / 机验 skill，不回本文。

## 四、依据供给、补充边界与术语转换

- **依据类型二分**：每条 TP/TC 落 `依据类型` 列，值域与机验契约见 `citation-verify`「清单表机器契约」。
  - `原文依据`：测试内容（含数值/阈值/枚举值/状态名/角色名等判定性内容）须可由 `出处锚点` 或澄清答复推导还原。
  - `方法论补充`：需求文档只写了功能/对象、没描述某个**测试维度、所属小类或该小类的关注点**，由模型**自行发散补测试内容**，用来提高覆盖率；发散依据为四份原文知识链（②§三 选型指南定组合 → ②§二 明细表列各小类「定义 / 关注点 / 典型场景举例」→ ③附录对应关系找到对应章节取详细测试项，如 ③§1.2 字段校验的输入域四要素与六大固定场景 → ④§五 模板库给展开方向、①§七 方法选型给用例设计方法，路径见 ④§7.1 / §7.2）或测试经验判断的应测点。例：资料只说「表单有姓名字段」，没写字段长度；②§二 1.2「基础功能 / 字段校验」关注点含「长度」，③§1.2 长度场景列了最小长度 / 最大长度 / 超长输入 / 零长度，就按这些补测试点与用例。
- **归类口径**：阶段 2 选静默生成的缺口、以及任何自由发挥生成出来的 TP/TC 一律标 `方法论补充`；选补充资料的，按用户答复写出的条目不再是自由发挥，标 `原文依据` 并挂对应 C 编号。
- **方法论补充的五条边界**（违反即虚构，QA 判阻塞）：
  1. 对象必须有原文锚点证明其存在：原文没有的字段/功能/状态/角色，不得生成对应测试内容；
  2. 不得补造业务规则（流程、权限、结果、状态流转）与提示文案；这类缺失仍走「待澄清问题」，不记入待澄清资料缺口清单；
  3. 静默生成时不写死具体数值/阈值/枚举值/文案，只写宽泛表述（如「测试姓名字段最大长度」「验证超长输入被拦截」），预期结果写语义级；
  4. 补充资料时，具体值以阶段 2 用户答复为依据，条目落 `原文依据`、`澄清依据` 标对应 C 编号，`出处锚点` 仍须有对象锚点；
  5. 两类条目都必须带 `出处锚点`，锚点口径见 `citation-verify`「锚点口径」第 7 条。
- 四份原文的「不臆造」针对**功能与对象**；方法论补充只按四份原文知识链或测试经验判断的维度/小类/关注点发散测试内容、不新增对象，与此不冲突。
- 业务特有测试规则不做系统级知识，由用户以输入资料方式提供：若用户提供了业务规则，则参考用户的规则；未提供时不叠加，缺项走澄清，不以方法论补充之名编造业务规则。
- **术语转换**：两篇原文的「优先级高」「按优先级排序」只表示该关注点必测，不生成优先级列，也不改变排序口径；排序按 `test-point-workflow` 方法链第 7 步执行。

## 五、关联文件：resources-index.md 概要书写规范

resources-index.md 是"查索引 → 精读片段"工作法的检索入口，概要质量直接决定定位效率。每行「概要」必须做到**不精读原文即可判断该节是否值得打开**，最低要求：

1. **实体齐全**：写明该节涉及的角色、对象、状态/字段名。状态流转行须逐个列出状态名，不得以"9 行任务状态转移"代之；列表类须写明列表内容是什么。
2. **数值/阈值保留**：人数、时限、版本号、条目数等数字直接进概要。
3. **异常分支显式**：该节含失败/降级/异常分支时，概要必须点出。
4. **做不到以上三点的超长短节**：直接摘引一句最能代表该节语义的**原文短语**（≤40 字）作概要，不改写。**≤40 字仅适用于本条的超长短节摘引**，不改变「概要一律 ≤50 字」的通则。
5. 概要一律基于原文内容书写，禁止臆造或外推；拿不准的以"需核对"标注并走澄清。

概要失真由 `material-quality-check`「检查项」判级，测试专家按修复回路的 `state/repair-log.md` 增量修复。
