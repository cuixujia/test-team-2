# 测试点生成与清单规范

功能点拆分、命名、颗粒度、模板库与生成流程按 `test-knowledge-canon`【段级索引】行段执行，取段范围由委派方给定。本文只承载产物清单规则与原文未覆盖的生成细则。

## 生成规则

### 生成红线

违反即虚构，QA 判阻塞：

1. 验证对象须有原文锚点；原文没有的字段、功能、状态、角色，不生成 TP。
2. 不补造业务规则与提示文案，不把未描述内容写成已描述。
3. 无依据支撑的内容静默生成，只写宽泛表述，不写死具体值、阈值、枚举值、文案。
4. 具体取值须以澄清答复为依据。
5. 三类依据的 TP 均须带原文锚点。

### 条目与命名细则

- 查询/筛选：并列且规则相同的查询项合为一条 TP，`用例展开重点` 逐项点名；PRD 明文规定不同结果的须拆。
- 描述不清：并列条件规则未明 → 按同一目标合一条，不自造规则。
- 并列双结果：同一处理逻辑可合，PRD 规定不同规则则拆。
- 「验证XX功能」式：直属 TC 承载两类及以上判定维度才合规，否则拆分；PRD 原词照抄不受此限。

### 排序规则

- 每个功能文件只含本功能 TP：先功能级，按正向 → 核心逻辑与状态 → 异常处理 → 边界与数据校验 → 其他排列，再以场景级收尾。
- 场景级 TP 归入流程起点或主承载功能的文件，归属不明查主件说明。排序由 QA 判定，生成方不回读重排。

## 清单结构

一个业务功能一个文件，按清单编号命名 `tp-{功能号}.json`，UTF-8 JSON。文件骨架：

```json
{
  "name": "F01-TP",
  "headers": ["AI测试点编号", "系统功能", "测试点", "类型", "测试维度", "所属小类", "用例展开重点", "依据类型", "备注"],
  "rows": [
    ["TP-001", "F01 需求新增", "验证新增界面展示正确性", "功能级", "基础功能", "功能正确性", ["UI：页面布局", "元素可见性"], "原文依据", ["prd1.md:5 => \"系统支持新增个人客户与对公客户\""]],
    ["TP-002", "F01 需求新增", "验证正常输入新增功能正确性", "功能级", "基础功能", "功能正确性", ["正向主流程", "数据落库", "状态变更"], "澄清依据(C-01)", ["prd1.md:15 => \"保存成功后状态置为待审核\""]],
    ["TP-003", "F01 需求新增", "验证新增输入域长度与字符约束", "功能级", "基础功能", "字段校验", ["姓名最大长度", "姓名特殊字符与空格", "年龄数值精度"], "补充条目", ["prd1.md:8 => \"表单字段：姓名、年龄\""]]
  ]
}
```

### 字段要求

顶层字段：

| 字段 | 要求 |
|---|---|
| name | `功能号-TP`，如 `F01-TP` |
| headers | 下列数据字段名数组，顺序固定、逐字用表内中文名 |
| rows | 每条 TP 一个数组，与 headers 一一对应，独占一个物理行 |

数据字段：

| 字段 | 要求 |
|---|---|
| AI测试点编号 | 各文件独立，自 `TP-001` 起三位递增，文件内永久稳定、不得复用。删除或插入条目不改其他编号，删除留空号；新增取本文件当前最大号加一，不回填空号。机验 `TP-\d+` |
| 系统功能 | scope 选中功能，`F01 需求新增` 格式；禁自创模块词 |
| 测试点 | 短语级 ≤30 字，PRD 叫法照抄；禁结果词、处理逻辑、具体值、并列双结果；`验证` 仅一次 |
| 类型 | 仅 `功能级` / `场景级`；单功能点为功能级，跨功能点链路为场景级 |
| 测试维度 | 单值，取《测试维度定义》「一、大类与测试维度总览」十枚举之一 |
| 所属小类 | 单值，须属于所选维度下《测试维度定义》「二、测试维度明细」合法小类；圈定小类每个至少 1 条 TP，人工对表，缺失阻塞 |
| 用例展开重点 | 数组，2~3 项以上，每项一个可独立判定分支；按 PRD 客观分支计数；字段校验另计《测试维度定义》1.2 字段校验关注点与《通用测试规则》1.2 六大固定测试场景、输入域联动；来源为《测试点生成指南》模板库右列 + 《通用测试规则》关注点；元描述不计入 N |
| 依据类型 | 逐条标注单值：`原文依据` = 验证方向与判定内容可由原文直接推导；`澄清依据(C-编号)` = 验证对象或判定口径原文未明确，依据用户澄清答复确立，C 编号须在 `state/clarifications.md` 存在；`补充条目` = 原文未覆盖测试方法论应设的维度或关注点，按测试方法论与资料理解发散补设； |
| 备注 | 数组，每项一条原文锚点；至少 1 项，一般 1~3 项 |
| 通用书写 | 单值字段为字符串，多值字段（用例展开重点、备注）为数组；字符串内禁真实换行；锚点摘抄含双引号时按 JSON 规则转义为 `\"` |
