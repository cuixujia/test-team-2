# 测试用例工作流（生成：test-expert · 质检：test-qa-expert）

## 甲 · 生成流程（阶段 5）

### 输入四件套（不重读原文）

scope.md 选中项、resources-index.md、clarifications.md、**output/tp/list.md**。TC 是 TP 的纯展开；仅在需要补充锚点证据时按索引回查原文片段。

### 方法选型（引用《通用测试方法论》§七"方法选型决策指南" + §五方法详解）

| 需求形态 | 选用方法 |
|---|---|
| 输入有明确区间/枚举/格式 | 等价类划分 + 边界值分析（下边界/上边界/内边界各取，min-1/min/max/max+1） |
| 多条件组合决定结果 | 决策表 / 因果图（剔除无效组合） |
| 有状态机/状态扭转 | 状态迁移（合法边、非法边、终态不可逆、超时流转） |
| 端到端业务链路 | 场景法（基本流 + 备选流逐条展开） |
| 多因子配置组合（多端/兼容性） | 正交实验（两两组合覆盖） |
| 经验性高风险点 | 错误推测（空值/重复提交/注入/超长，作补充不单用） |

用例类型三件套基线：每条 TP 基线展开 **2~3 条**——至少 1 条正向、1 条反向/异常；有输入域的必须有边界值用例。禁止为凑数复制改名。

### 落盘模板（output/tc/list.md，11 列，列名与机验绑定不得改）

```markdown
# 测试用例清单

| 编号 | 关联TP | 用例名称 | 用例类型 | 优先级 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点 |
|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | TP-002 | 新增-全部必填合法输入 | 正向 | P0 | 已登录且有新增入口 | 客户名称=张三；证件号=110101199001011234 | 1.进入新增页 2.填写全部必填项 3.保存 | 保存成功；列表出现该记录；状态=待审核 | - | prd1.md:15 => "保存成功后状态置为待审核" |
| TC-002 | TP-002 | 新增-客户名称超长 | 边界 | P1 | 已登录且有新增入口 | 客户名称=51个字符 | 1.进入新增页 2.名称填51字符 3.填写其余必填项 4.保存 | 拦截并提示名称超长；不落库 | C-01 | prd1.md:12 => "客户名称长度不超过50个字符" |
```

填写规范（每列的验收标准）：
- 编号 `TC-001` 全局递增；关联TP = 单个 TP 编号
- 用例类型：`正向 / 反向 / 边界`；优先级：`P0`＝正向主链路与核心业务规则，`P1`＝异常、边界、状态扭转，`P2`＝其余
- 前置条件：可核对的事实（权限入口/初始状态/数据存在性）
- 测试数据：**具体值**（"51个字符"这类可执行描述允许，"超长数据"不允许）
- 操作步骤：原子动作序列，可照做
- 预期结果：**可判定**的结果（页面反馈/数据落库/状态值/消息触发）；禁止"符合预期"类模糊语
- 澄清依据：`-` / `C-01` / `C-01(默认)`
- 出处锚点：引用与该用例最直接相关的原文位置（通常继承关联 TP 的锚点，也可按需补充；行内多锚点 ` ;; ` 分隔；单元格禁现 `|`）

### 送检门槛

跑 `verify_citation.py`（TP/TC 全参）：`failures` = 0 才送检；`warnings`（TP 覆盖缺口）逐条人工确认，无 TC 关联的 TP 必须有书面理由记入 state.md。

## 乙 · 质检维度（阶段 6，QA 全量检；大清单按功能分批连续检完）

| # | 维度 | 判定要点 | 分级参考 |
|---|---|---|---|
| 1 | TP 覆盖完整性 | 每个 TP ≥2~3 条用例且正/反/边界分布合理；缺反向或边界 → 问题 | 缺失→阻塞；偏少→重大 |
| 2 | 语义一致 | TC 确实在验证其关联 TP，不是跑题用例 | 跑题→阻塞 |
| 3 | 硬凑检测 | 同值改名、伪边界、把两条用例拆成四条凑数 | 重大 |
| 4 | 字段质量 | 预期结果可判定（无"符合预期"）；测试数据具体；步骤可照做；前置条件可核对 | 重大 |
| 5 | 用例重复 | 两条 TC 实质相同（同 TP+同数据+同步骤+同预期） | 重大 |
| 6 | 锚点抽验 | 每功能模块 ≥3 条：md 直读；docx/xlsx 用 inspect_anchor.py | 不实→阻塞 |
| 7 | 优先级合理性 | P0 与主链路/核心规则对应；异常边界不落 P0 | 一般 |
| 8 | 澄清/默认 | 澄清编号真实、语义一致；`(默认)` 条目重点核 | 误用→阻塞；风险→重大 |

## 报告格式（qa-tc.md，追加 `## R{N}` 小节，只追加不改写）

```markdown
## R{N}

**检查范围**：覆盖的 TP 与批次

### 问题清单
| 问题编号 | 分级 | 条目 | 问题描述 | 证据锚点 | 建议 |
|---|---|---|---|---|---|
| Q-TC-R1-01 | 重大 | TC-012 | 两条同值边界用例重复 | prd1.md:12 => "……" | 合并为一条 |

### 对照表复检（R2+）
| 问题编号 | 复检结果 | 核对说明 |
|---|---|---|

### 新增条目检查（R2+）
……

### 收敛判定
收敛 / 未收敛（剩余阻塞项：…）
```

R2+ 增量复检：只核 repair-log `## TC-R{n}` 小节条目 + 新增条目。收敛 = 无阻塞级问题。

## 纪律

QA 只检不修、每问题必附证据锚点；经理禁止自检替代本质检；模板列名是机器契约，增删列必须先改 skill `citation-verify` 的脚本再改本模板。
