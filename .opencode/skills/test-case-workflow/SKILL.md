# 测试用例工作流（生成：测试专家 agent `test-expert` · 质检：质检专家 agent `qa-expert`）

## 甲 · 生成流程（阶段 5）

### 输入四件套（不重读原文）

scope.md 选中项、resources-index.md、clarifications.md、**output/tp/list.md**。TC 是 TP 的纯展开；仅在需要补充锚点证据时按索引回查原文片段。

### 方法选型（引用《通用测试方法论》§七"方法选型决策指南" + §五方法详解）

| 需求形态 | 选用方法 |
|---|---|
| 输入有明确区间/枚举/格式 | 等价类划分 + 边界值分析（下边界/上边界/内边界各取，min-1/min/max/max+1） |
| 多条件组合决定结果 | 决策表 / 因果图（剔除无效组合） |
| 有状态机/状态扭转 | 状态迁移（合法边、非法边、终态不可逆、超时流转） |
| 端到端业务链路 | 场景法（基本流 + 备选流逐条展开） |
| 多因子配置组合（多端/兼容性） | 正交实验（两两组合覆盖） |
| 经验性高风险点 | 错误推测（空值/重复提交/注入/超长，作补充不单用） |

方法详解与取值按《通用测试方法论》执行：取值依知识③§1.2（输入域四要素、六大固定场景）、知识①§5.1.1（等价类代表值）与 §5.1.2（边界值六点）；方法详解按需查 §五。

用例类型三件套基线（裁决一/五，登记表见 skill `test-point-workflow`）：每条 TP 至少展开 2 条——至少 1 条正向、1 条反向/异常；有输入域的必须有边界值用例（上限以维度数封顶、不强凑 3）。禁止为凑数复制改名。

### 落盘模板（output/tc/list.md，11 列，列名与机验 `TC_REQUIRED` 逐字一致）

```
编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点
```

```markdown
# 测试用例清单

| 编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点 |
|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | F01 · 需求创建 | TP-002 | 新增-全部必填合法输入验证 | 正向 | 已登录且有新增入口 | 客户名称=张三；证件号=110101199001011234 | 1.进入新增页 2.填写全部必填项 3.保存 | 保存成功；列表出现该记录；状态=待审核 | - | prd1.md:15 => "保存成功后状态置为待审核" |
| TC-002 | F01 · 需求创建 | TP-002 | 新增时输入超限客户名称验证 | 反向 | 已登录且有新增入口 | 客户名称=51个字符 | 1.进入新增页 2.名称填51字符 3.填写其余必填项 4.保存 | 拦截并提示名称超长；不落库 | C-01 | prd1.md:12 => "客户名称长度不超过50个字符" |
```

| 字段 | 取值规则 |
|---|---|
| 编号 | `TC-001` 三位数字起步 |
| 关联业务功能 | 主 TP 所属业务功能，取值同 TP 表（F 编号 + PRD 原文名称） |
| 关联TP | 恰好一个，格式 `TP-xxx`，必须存在于一 TP 清单（一 TC = 一 TP，裁决二，见 skill `test-point-workflow` 裁决登记表） |
| 用例名称 / 测试数据 / 操作步骤 / 预期结果 | 依下方【TC 四列判据】 |
| 用例类型 | 仅 `正向` / `反向` / `边界` / `场景` / `异常`（**纯白名单，无括注变体**，保证统计不失真） |
| 澄清依据 | 无：`-`；有：`C-编号` 或 `C-编号(默认)`；多值 ` ;; ` 分隔；编号必须存在于 clarifications.md |
| 出处锚点 | 引用与该用例最直接相关的原文位置（通常继承关联 TP 的锚点，也可按需补充）；按 skill `citation-verify` 锚点口径 |

**取消优先级字段**：TP、TC 均不设优先级列。排序即优先级——清单顺序 = 业务功能（关口 1 选定序）簇 → 簇内测试点按知识④§六步骤 6 → 测试用例承接其主 TP 所在顺序、簇内同法则排列（裁决六 B2）。

### TC 四列判据（标题 / 测试数据 / 操作步骤 / 预期结果）

> 方法论（取什么值、按什么方法铺场景）不在本节复述：取值依知识③§1.2与知识①§5.1.1/§5.1.2，见方法选型节。

**标题**
- 结构 = **场景 + 预期落点**：以「场景…验证」收口式（如「编辑风险时上传空文件验证」）或「场景 + 预期」陈述式（如「金额超单笔限额，交易拒绝并提示」）承载均可。
- **一次判定原则**：一个标题只承载一次判定。预期结果可含多个观察点（如「余额不变 + 流水生成」），但须同属一次判定；承载第二种判定即拆分为两条用例。

**测试数据**
- 给**具体值**或可执行构造方法，金额/字段给到具体数值；禁止「系统正常」「适当数据」类可随意替代的表述。
- 值的选择按知识③§1.2 四要素/六场景、知识①等价类与边界点执行。

**操作步骤**
- **动词开头、编号分步**（「1.」与「1、」均可）；不含歧义词（「等一下」「适当输入」类禁用）。
- **业务等待例外**：等待对象为系统行为（定时任务触发、状态扭转、异步回调、消息到达）且后续步骤含该行为的可判定观察点时，写「等待/触发」合规；等待对象为执行者判断或无法判定的等待（「等一会」「稍候再看」）仍违规。

**预期结果**
- 具体到**可观察物**：数据值/一致性（值类判定）、界面元素状态（高亮/灰显/置灰）、提示文案、状态变更、消息推送内容五类承载形态任一；可直接判 pass/fail。
- 错误提示指向**具体字段与原因**，不用通用模糊提示（知识③§1.2 判定规则）。

### 送检门槛

`failures` = 0 才送检（机验命令与逐列自校见 skill `citation-verify`"生成端送检前"及"送检前自校"节）；重试与异常处置（exit 2 / 三振上限）按测试专家机验规则。`warnings`（TP 覆盖缺口）逐条人工确认，无 TC 关联的 TP 必须有书面理由记入 state.md。

## 乙 · 质检维度（阶段 6，QA 全量检；大清单按功能分批连续检完）

| # | 维度 | 判定要点 | 分级参考 |
|---|---|---|---|
| 1 | TP 覆盖完整性 | 每个 TP ≥2 条用例且正/反/边界分布合理；缺反向或边界 → 问题 | 缺失→阻塞；偏少→重大 |
| 2 | 语义一致 | TC 确实在验证其关联 TP，不是跑题用例 | 跑题→阻塞 |
| 3 | 硬凑检测 | 同值改名、伪边界、把两条用例拆成四条凑数 | 重大 |
| 4 | 字段质量 | 按甲节【TC 四列判据】逐列核查（含一次判定原则、歧义等待例外） | 重大 |
| 5 | 用例重复 | 两条 TC 实质相同（同 TP+同数据+同步骤+同预期） | 重大 |
| 6 | 锚点抽验 | 每功能模块 ≥3 条：md 直读；docx/xlsx 用 inspect_anchor.py | 不实→阻塞 |
| 7 | 排序 | 用例承接其主 TP 所在顺序、簇内同法则（裁决六 B2，见 skill `test-point-workflow`） | 一般 |
| 8 | 澄清/默认 | 澄清编号真实、语义一致；`(默认)` 条目重点核 | 误用→阻塞；风险→重大 |

## 报告格式（qa-tc.md，追加 `## R{N}` 小节，只追加不改写）

```markdown
## R{N}

**检查范围**：覆盖的 TP 与批次

### 问题清单
| 问题编号 | 分级 | 条目 | 问题描述 | 证据锚点 | 建议 |
|---|---|---|---|---|---|
| Q-TC-R1-01 | 重大 | TC-012 | 两条同值边界用例重复 | prd1.md:12 => "……" | 合并为一条 |

### 对照表复检（R2+）
| 问题编号 | 复检结果 | 核对说明 |
|---|---|---|

### 新增条目检查（R2+）
……

### 收敛判定
收敛 / 未收敛（剩余阻塞项：…）
```

R2+ 增量复检：只核 repair-log `## TC-R{n}` 小节条目 + 新增条目。收敛 = 无阻塞级问题。

## 纪律

QA 只检不修、每问题必附证据锚点；测试专家禁止自检替代质检专家检；模板列名是机器契约，增删列必须先改 skill `citation-verify` 的机验脚本再改本模板。格式问题（锚点格式/表头列名/摘抄长度/横线）由测试专家机验前置拦下，**不进质检范围**。
