# 测试用例判据（TC）

## 生成判据

### 方法选型（引用《通用测试方法论》§七"方法选型决策指南" + §五方法详解）

| 需求形态 | 选用方法 |
|---|---|
| 输入有明确区间/枚举/格式 | 等价类划分 + 边界值分析（下边界/上边界/内边界各取，min-1/min/max/max+1） |
| 多条件组合决定结果 | 决策表 / 因果图（剔除无效组合） |
| 有状态机/状态扭转 | 状态迁移（合法边、非法边、终态不可逆、超时流转） |
| 端到端业务链路 | 场景法（基本流 + 备选流逐条展开） |
| 多因子配置组合（多端/兼容性） | 正交实验（两两组合覆盖） |
| 经验性高风险点 | 错误推测（按【展开结构与经验场景判据】固化清单执行，作补充不单用） |

方法详解与取值按《通用测试方法论》执行：取值依知识③§1.2（输入域四要素、六大固定场景）、知识①§5.1.1（等价类代表值）与 §5.1.2（边界值六点）；方法详解按需查 §五。**选型成果随条目落 `测试方法` 列**（单值主要方法；一条 TP 的展开通常同方法，跨方法时按用例各自标注）。

### 展开结构与经验场景判据（输入域 / 边界 / 经验场景）

- **双源逐项展开（每条 TP 生成 TC 前必做，两个输入源并重）**：TC 按「① 该 TP 的 `用例展开重点`（N 项逐项）＋ ② 知识链全集对照」合并去重后的项集逐项落用例。知识链对照按该 TP 的 `测试维度/所属小类` 反查知识清单——②该小类的「定义 / 关注点 / 典型场景举例」→ ③对应章节详细测试项（如 ③§1.2 六大固定场景）→ ①§七 方法选型 → ④§五 模板库展开方向——得到该形态**命中的关注点全集**。逐项判定落哪一类：资料已描述的落 `原文依据`；资料未描述、知识链要求的落 `方法论补充`（边界见 `test-knowledge-canon` §四）；两源重复的关注点只落一条、不重复计数。TC 数 M 不得低于合并去重后的项数，禁因展开重点没点名就跳过知识链命中的关注点，也禁只按知识链发散而丢掉展开重点已点名的项。
- **输入域展开乘法原则**（仅适用于字段校验/输入域形态的 TP，其他形态不强制矩阵）：展开按「字段清单 × 约束矩阵」逐字段落用例（必填/长度/格式/枚举/特殊字符逐项）；**空值遍历逐字段一条**——每条只留空一个必填字段、其余填合法值，判定该字段单独报错；**每个输入域表单必补 1 条全字段空值用例**（六大固定场景「空场景」的全部字段为空，见《通用测试规则》六大固定场景），字段校验类计数相应 +1。约束矩阵 = 原文已给约束 + 按②§二 1.2「字段校验」关注点 + ③§1.2 六大固定场景发散的约束（长度/格式/枚举/精度/特殊字符/空格/脚本）；由发散约束展开的用例落 `方法论补充`，静默生成时 `测试数据` / `预期结果` 只写宽泛表述（最大长度/超长/特殊字符），不写具体值，补充资料按 C 编号答复写具体内容。
- **边界配对原则**：数值/长度约束的边界展开为「恰好达界 + 越界」配对（max 与 max+1、min 与 min-1，承接知识①§5.1.2 六点法）；精度类（小数位/舍入）对称处理；禁「超出长度上限」式单侧笼统。**"封顶"只作用于 TP 拆分方向**（一条 TP 不因维度多而无限细分），**不构成 TC 数量的上限**——TC 数量下限见 `citation-verify`「清单表机器契约」，`用例展开重点` 项数 N 是展开数量目标（M≥N，见「展开数量守恒」）。
- **经验场景固化清单**（错误推测法的触发条件：命中需求形态才展开，不机械全覆盖，以补充用例承载、方法主选型不变）：
  - 文本输入域需求 → 注入/XSS 转义、特殊字符（@#$% 等）、超长、空值、重复提交
  - 列表/查询类需求 → 分页与排序保持、连续操作缓存残留
  - 复制类功能 → 数据独立性（修改原件不影响副本，知识③复制类模板承接）

### 展开数量守恒

逐 TP 直属 TC 数下限见 `citation-verify`「清单表机器契约」；`M=0` 由覆盖缺口 warning 承载并须书面理由记 `state.md`。

`用例展开重点` 的项数 N 按 TP 形态查下表核算，是逐 TP 的**展开数量目标**：**每一项至少对应 1 条直属 TC，M 不得低于 N**；知识链对照命中的关注点同样计入下限——**M 不得低于「N 项 ∪ 知识链命中关注点」合并去重后的项数**（双源口径见「展开结构与经验场景判据」首条）。`M≥2` 只是机验下限，**M 停在下限而目标项数 >2 仍只落 2 条即"展开不足"，属反向凑数**；人工复核发现不足时，回到该 TP 的 `用例展开重点` 与知识链全集逐项补齐，不得靠补空壳、复制改名绕过：

| TP 形态（所属小类） | N 的核算建议 | 示例 |
|---|---|---|
| 字段校验 / 接口参数校验 | 字段数 × 约束类型数（原文已给 + 按②§二 1.2「字段校验」关注点 + ③§1.2 六大固定场景发散：必填/长度/格式/枚举/精度/特殊字符/空格/脚本/有效性），且**空值逐字段各一条 + 全字段空值 1 条** | 6 个任务字段（必填+长度+SSO有效性）→ 11 条 |
| 状态流转 | 合法边逐条 + 非法扭转 ≥1 | 7 条合法边 → ≥8 条 |
| 查询/筛选 | 查询项逐项 + 组合筛选 1 + 空结果 1 | 状态/领域/时间 → ≥5 条 |
| 权限控制 | 角色 × 操作矩阵的有效格逐格 + 越权反向 ≥1 | 承接人/派发人 × 承接/撤回 → ≥5 条 |
| 场景级（主流程） | 基本流 1 + 各备选流逐条 | 3 个备选流 → ≥4 条 |
| 可靠性与稳定性（容错） | 外部依赖逐项 + 开关分支逐项 | 5 个外部系统 → ≥5 条 |
| 数据一致性 / 数据正确性 | 各对比基准/一致性方向逐项 | 订单/库存/流水三方 → ≥3 条 |
| 其他形态 | 展开重点列点名的项数 | — |

- **条数来自客观计数，不来自"再补一条显得充实"**：禁止为凑数复制改名、伪边界、同值换装。
- 有输入域的必须含边界值用例（达界 + 越界配对）；字段校验类必须落在乘法原则上方的「字段清单 × 约束矩阵」内，并含 1 条全字段空值用例。

| 字段 | 取值规则 |
|---|---|
| 编号 | `TC-001` 三位数字起步；重排后**必须重编号**（连续无跳号），与 TP 对称 |
| 关联业务功能 | 主 TP 所属业务功能，取值同 TP 表（第一个空格分隔 F 编号与名称）；**join 一致性：逐字等于其主 TP 的 `关联业务功能`**（防主从挂错簇，机验） |
| 关联TP | **双信息：第一个空格分隔编号段与名称段**（如 `TP-002 验证正常输入新增功能正确性`）。编号段：恰好一个（主 TP），格式 `TP-xxx`，必须存在于 TP 清单，**一 TC = 一 TP** 不设多挂靠（"顺带验证"不构成多挂靠理由，跨功能点链路由场景级 TP 承载，见 `test-point-workflow`）；名称段：**逐字取自 TP 清单该 TP 的 `测试点名称`**，不得缩写、改写、同义替换；TP 侧修复导致测试点名称变更时，关联 TC 的名称段同步更新（名称段不一致由机验直接拦截） |
| 用例名称 / 测试数据 / 操作步骤 / 预期结果 | 依【TC 四列判据】 |
| 用例类型 | 仅 `正向` / `反向` / `边界` / `场景` / `异常`（**纯白名单，无括注变体**，保证统计不失真） |
| 测试方法 | 单值=该用例采用的主要设计方法，六枚举白名单：`等价类+边界值` / `决策表` / `状态迁移` / `场景法` / `正交实验` / `错误推测`（因果图按决策表口径落值）；来源=方法选型决策指南按需求形态匹配（选型成果随条目落本列，机验白名单见 `citation-verify`） |
| 依据类型 | 仅 `原文依据` / `方法论补充`（值域机验见 `citation-verify`）。`原文依据` = 判定性内容由 `出处锚点` 或澄清答复推导；`方法论补充` = 资料未描述、由模型自由发挥补出的测试内容（发散依据为四份原文知识链或测试经验判断的应测点），定义与五条边界见 `test-knowledge-canon` §四。**静默生成的缺口与任何自由发挥用例一律 `方法论补充`；补充资料后按答复写出的用例落 `原文依据`**。同一 TP 下两类用例可并存，逐条标注、不整批打包；静默生成不写具体值且 `澄清依据` 写 `-`，补充资料按答复写具体内容并标对应 C 编号 |
| 澄清依据 | 无：`-`；有：`C-编号` 或 `C-编号(默认)`；多值 ` ;; ` 分隔；编号必须存在于 clarifications.md |
| 出处锚点 | 引用与该用例最直接相关的原文位置（通常继承关联 TP 的锚点，也可按需补充）；按 `citation-verify` 锚点口径。两类用例都须有对象锚点证明验证对象在原文存在；`方法论补充` 的锚点不要求支撑发散出的测试内容 |

**分隔符口径**：编号与名称的展示分隔用**空格**（关联业务功能、关联TP）；多值项（锚点、澄清依据、用例展开重点）仍用 ` ;; `；**`<br>` 仅限操作步骤列**（步骤间换行），锚点/澄清依据/测试数据等其他列禁用。

**优先级字段**：见 `citation-verify`「清单表机器契约」。

**排序规则**：主 TP 排在哪，它的用例就排在哪。

- 同一业务功能的用例排在一起；同一条 TP 的用例也排在一起，中间不插别的 TP。
- 不许按用例类型（正向/反向/边界）或测试方法把整张表重新排序；场景级 TP 的用例也不集中挪到清单最后。
- 一条 TP 内部的用例按 正向 → 反向/异常 → 边界 排。
- 排序须人工逐行核对；口径见 `citation-verify`「清单表机器契约」。

### TC 四列判据（标题 / 测试数据 / 操作步骤 / 预期结果）

> 取值依知识③§1.2 与知识①§5.1.1/§5.1.2，见方法选型节。

**内容可追溯性三层口径**：四列是设计推导产物，不要求逐字出自资料，但出处分层——

| 内容类型 | 出处要求 |
|---|---|
| **判定性内容**（数值/阈值/枚举值/状态名/角色名） | 按 `依据类型` 分路：`原文依据` 必须可由关联 TP 锚点或澄清答复**推导还原**（锚点写上限 25 → 测 26 是合法推导；锚点无 25 而写 25 即臆造）；`方法论补充` **不得写死具体值**——静默生成只写宽泛表述（最大值/最小值/超长/特殊字符/空格/脚本）；补充资料的具体值以阶段 2 答复为依据，对应用例落 `原文依据` 且 `澄清依据` 须标该 C 编号；两类用例的字段名/状态名/角色名一律照抄原文术语 |
| **提示文案** | 资料给了文案→照抄锚点原文；没给→写语义级预期（如「提示工作空间 ID 必填」），禁杜撰具体文案；`方法论补充` 用例同样禁写具体文案 |
| **编排性内容**（步骤顺序/前置账号与环境/构造方法） | 测试设计自由度，不受资料逐字约束；涉及的状态名/角色名/字段名须与资料术语一致 |

**依据类型分路口径**：`原文依据` 用例维持严格溯源；`方法论补充` 用例的补充范围与静默/补充资料取值规则见 `test-knowledge-canon` §四，验证对象必须有原文对象锚点，不得出现原文没有的字段/功能。自由发挥生成的用例（含静默生成）一律 `方法论补充`，补充资料后按答复写出的用例落 `原文依据`。同一 TP 下两类用例可并存（必填校验为原文依据，按②§二 1.2「字段校验」关注点 + ③§1.2 六大固定场景发散的长度/精度/枚举/特殊字符为方法论补充），`依据类型` 逐条标注，不按 TP 整批打包。

**术语落名禁泛化**：资料已明确的角色名/状态名/字段名/文案，用例中必须照抄 PRD 叫法（如「测试管理人/负责人」不得写成「有权限的用户」）；资料未给才允许语义级预期表述。前置条件/测试数据/操作步骤/预期结果四列一体适用。

**标题**
- 结构 = **「验证 + 场景 + 预期落点」单式**：一律以「验证」开头（与 TP 名称风格统一），预期承载在句中或句尾（如「验证金额超单笔限额时交易拒绝并提示」「验证编辑风险上传空文件被拦截」）。
- **一次判定原则**：一个标题只承载一次判定。预期结果可含多个观察点（如「余额不变 + 流水生成」），但须同属一次判定；承载第二种判定即拆分为两条用例。
- **短语级 ≤30 字**（与 TP 名称对称）。
- **对象词沿用主 TP 名称中的 PRD 叫法**，不自创同义词——F→TP→TC 名称链检索键一致。
- **同 TP 直属用例标题以差异点区分**（状态/数据语义/场景分支）；仅以序号或「验证 1 / 验证 2」式区分判硬凑（归质检维度 4）。
- **标题禁承载具体数据字面值**（如「51 个字符」「WS001」，写测试数据列）；场景语义词（上边界/超长/空值/缺省）允许。

**测试数据**
- 两种承载形态（可并存，以「；」分隔）：
  - **赋值式**：`字段=值`，多值以「；」分隔；日期区间写「起 至 止」；构造方法括注「（构造：…）」；多记录须逐条枚举或给出生成规则（如「编号分别为 X 和 Y」），禁「多条数据」式含糊。
  - **状态描述式**：场景背景/数据就绪态按自然语句书写（含具体数值，如「需求 R1 已关联 [D001]」），不因自然语句含冒号判错。
- **同一承载形态内符号一致**：赋值式内禁「：」「=」「，」混排作分隔符。
- 给**具体值**或可执行构造方法，金额/字段给到具体数值；禁止「系统正常」「适当数据」类可随意替代的表述。
- 值的选择按知识③§1.2 四要素/六场景、知识①等价类与边界点执行。

**操作步骤**
- **动词开头、编号分步**（「1.」与「1、」均可），**步骤间以 `<br>` 分隔**（md 单元格内换行：展示层直接多行、导出 xlsx 转 `\n`）；不含歧义词（「等一下」「适当输入」类禁用）。
- **业务等待例外**：等待对象为系统行为（定时任务触发、状态扭转、异步回调、消息到达）且后续步骤含该行为的可判定观察点时，写「等待/触发」合规；等待对象为执行者判断或无法判定的等待（「等一会」「稍候再看」）仍违规。
- **准备类步骤归属判据**：准备产物被后续步骤引用或观察（如「在源平台创建记录并记录编号」供后续核对）→ 允许作为前置编号步骤；纯环境置备、无中间观察（如「服务置为不可用」）→ 写前置条件列，不进步骤。

**预期结果**
- 具体到**可观察物**：数据值/一致性（值类判定）、界面元素状态（高亮/灰显/置灰）、提示文案、状态变更、消息推送内容五类承载形态任一；可直接判 pass/fail。
- **一致性判定必须点名对比基准**（源系统/前端展示/数据库/导出文件/源平台），禁「数据准确无误」式无基准断言。
- 错误提示指向**具体字段与原因**，不用通用模糊提示（知识③§1.2 判定规则）。

## 质检判据（九维）

| # | 维度 | 判定要点 | 分级参考 |
|---|---|---|---|
| 1 | TP 覆盖完整性 | **数量守恒逐条核对**：每个 TP 的直属 TC 数 `M≥2`（`M=0` 由覆盖缺口 warning 承载并须书面理由记 `state.md`）——**`M≥1` 且 `<2` 判展开不足**，不得以"已满足 1 条"通过；`用例展开重点` 项数 N 按形态表核算，逐 TP 核对 **`M≥N`，`M<N` 即判"展开不足"（阻塞）**（核算口径：字段×约束、状态边数、查询项数、角色×操作、外部依赖数）；正/反/边界分布合理，缺反向或边界 → 问题；**字段校验类抽查展开矩阵完整性**（字段×约束含方法论补充约束、空值逐字段遍历、**全字段空值 1 条**）；**边界配对完整**（达界+越界）；**经验场景清单命中形态零覆盖**（注入/特殊字符/分页排序/复制独立性等）；**知识链全集对照**：逐 TP 按 `测试维度/所属小类` 反查知识清单，命中关注点零覆盖 → 漏项；**均一化红线**：过半 TP 的 M 完全相同且与算法建议不符 → 判整批按 TP 均摊凑数；**待澄清资料缺口决策复查**：阶段 2 缺口清单列出的测试维度/小类/关注点逐项核对是否有对应 TC，同一 TP 下 `原文依据` / `方法论补充` 可并存但 `依据类型` 须逐条标注 | 阻塞（M<2、M<N、均一化）；矩阵/配对/清单缺项→重大；方法论维度漏补→重大 |
| 2 | 方法适配 | TP 需求形态 ↔ `测试方法` 匹配（如状态流转类 TP 的直属 TC 全非状态迁移、多条件组合类全无决策表 → 提示）；纯人工判据 | 错配→一般 |
| 3 | 语义一致（按 `依据类型` 分路） | TC 确实在验证其关联 TP，不是跑题用例；`原文依据`：**判定性内容（数值/枚举/文案/状态名）须可由关联 TP 锚点或澄清答复推导，推导不出判臆造**；`方法论补充`：只核对象锚点真实且验证对象确在原文、补充的测试维度/所属小类/关注点属于知识链或测试经验判断的应测范围且按该关注点发散、静默生成未写死具体值、未借补充之名补造业务规则或新增字段/功能，**不得仅因"原文没描述该维度/小类"判臆造**（边界见 `test-knowledge-canon` §四） | 跑题→阻塞；臆造/虚构对象→阻塞 |
| 4 | 硬凑检测 | 同值改名、伪边界、把两条用例拆成四条凑数；**反向凑数**：不问 PRD 有多少判定分支、也不顾 `用例展开重点` 的逐项展开要求（M≥N），按 TP 均摊固定条数；**空壳充数**：为满足数量下限补入无独立判定、与他人重复的用例；**方法论补充凑数**：借补充之名复制改名、把同一约束换个词重复落用例，同样判硬凑 | 重大（均摊/空壳→阻塞） |
| 5 | 字段质量 | 按【TC 四列判据】逐列核查（含一次判定原则、歧义等待例外、测试数据两形态、`<br>` 换行、一致性对比基准）；**术语落名：资料已明确的角色/状态/字段/文案泛化表述判错** | 重大 |
| 6 | 用例重复 | 两条 TC 实质相同（同 TP+同数据+同步骤+同预期） | 重大 |
| 7 | 锚点抽验 | 每功能模块 ≥3 条：md 直读；docx/xlsx 用 inspect_anchor.py；两类用例都须有对象锚点，`原文依据` 的锚点还须支撑判定性内容，`方法论补充` 的锚点只需证明验证对象在原文存在；原文没有的字段/功能却有用例 → 阻塞 | 不实→阻塞；虚构对象→阻塞 |
| 8 | 排序 | 按 `test-point-workflow` 方法链第 7 步与本 skill「落盘模板」的排序规则人工核对：用例有没有跟着主 TP 走，同一业务功能、同一 TP 的用例是否各自排在一起；段内是否正→反→边界；场景级 TP 的用例是否留在本功能段内 | 一般（段内乱序）；功能段被打断、同一 TP 用例被穿插、场景级用例跑到清单末尾 → 重大 |
| 9 | 澄清/默认 | 澄清编号真实、语义一致；`(默认)` 条目重点核；**待澄清资料缺口决策一致性**：静默生成与自由发挥的用例一律 `方法论补充`、不得挂 C 编号、不得写具体值，补充资料的用例落 `原文依据`、须标对应 C 编号且具体值与答复一致 | 误用→阻塞；风险→重大 |
