# 测试用例工作流（生成：测试专家 agent `test-expert` · 质检：质检专家 agent `qa-expert`）

## 甲 · 生成流程（阶段 5）

### 输入四件套（不重读原文）

scope.md 选中项、resources-index.md、clarifications.md、**output/tp/list.md**。TC 是 TP 的纯展开；仅在需要补充锚点证据时按索引回查原文片段。

### 方法选型（引用《通用测试方法论》§七"方法选型决策指南" + §五方法详解）

| 需求形态 | 选用方法 |
|---|---|
| 输入有明确区间/枚举/格式 | 等价类划分 + 边界值分析（下边界/上边界/内边界各取，min-1/min/max/max+1） |
| 多条件组合决定结果 | 决策表 / 因果图（剔除无效组合） |
| 有状态机/状态扭转 | 状态迁移（合法边、非法边、终态不可逆、超时流转） |
| 端到端业务链路 | 场景法（基本流 + 备选流逐条展开） |
| 多因子配置组合（多端/兼容性） | 正交实验（两两组合覆盖） |
| 经验性高风险点 | 错误推测（按下方【展开结构与经验场景判据】固化清单执行，作补充不单用） |

方法详解与取值按《通用测试方法论》执行：取值依知识③§1.2（输入域四要素、六大固定场景）、知识①§5.1.1（等价类代表值）与 §5.1.2（边界值六点）；方法详解按需查 §五。**选型成果随条目落 `测试方法` 列**（单值主要方法；一条 TP 的展开通常同方法，跨方法时按用例各自标注）。

### 展开结构与经验场景判据（输入域 / 边界 / 经验场景）

- **输入域展开乘法原则**（仅适用于字段校验/输入域形态的 TP，其他形态不强制矩阵）：展开按「字段清单 × 约束矩阵」逐字段落用例（必填/长度/格式/枚举/特殊字符逐项）；**空值遍历逐字段一条**——每条只留空一个必填字段、其余填合法值，判定该字段单独报错；全字段组合空值用例仅在 PRD 明文规定「一次性提示全部缺失字段」时允许。
- **边界配对原则**：数值/长度约束的边界展开为「恰好达界 + 越界」配对（max 与 max+1、min 与 min-1，承接知识①§5.1.2 六点法）；精度类（小数位/舍入）对称处理；禁「超出长度上限」式单侧笼统。维度数封顶口径不变——封顶限 TP 层展开方向，配对是 TC 层展开结构。
- **经验场景固化清单**（错误推测法的触发条件：命中需求形态才展开，不机械全覆盖，以补充用例承载、方法主选型不变）：
  - 文本输入域需求 → 注入/XSS 转义、特殊字符（@#$% 等）、超长、空值、重复提交
  - 列表/查询类需求 → 分页与排序保持、连续操作缓存残留
  - 复制类功能 → 数据独立性（修改原件不影响副本，知识③复制类模板承接）

用例类型三件套基线：每条 TP 至少展开 2 条——至少 1 条正向、1 条反向/异常；有输入域的必须有边界值用例（上限以维度数封顶、不强凑 3；"维度数"=该 TP 验证目标内可分辨的判定分支数，如"修改限双状态"承载 4 状态边界=4 维度；**字段校验/输入域形态 TP 的判定分支数按「字段×约束」计，与乘法原则一致**）。禁止为凑数复制改名。

### 落盘模板（output/tc/list.md，12 列，列名与机验 `TC_REQUIRED` 逐字一致）

```
编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 测试方法 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点
```

| 编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 测试方法 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| TC-001 | F01 需求新增 | TP-002 验证正常输入新增功能正确性 | 验证全部必填合法输入新增成功 | 正向 | 等价类+边界值 | 已登录且有新增入口 | 客户名称=张三；证件号=110101199001011234 | 1.进入新增页<br>2.填写全部必填项<br>3.保存 | 保存成功；列表出现该记录；状态=待审核 | - | prd1.md:15 => "保存成功后状态置为待审核" |

| 字段 | 取值规则 |
|---|---|
| 编号 | `TC-001` 三位数字起步；重排后**必须重编号**（连续无跳号），与 TP 对称 |
| 关联业务功能 | 主 TP 所属业务功能，取值同 TP 表（第一个空格分隔 F 编号与名称）；**join 一致性：逐字等于其主 TP 的 `关联业务功能`**（防主从挂错簇，机验） |
| 关联TP | **双信息：第一个空格分隔编号段与名称段**（如 `TP-002 验证正常输入新增功能正确性`）。编号段：恰好一个（主 TP），格式 `TP-xxx`，必须存在于 TP 清单，**一 TC = 一 TP** 不设多挂靠（"顺带验证"不构成多挂靠理由，跨功能点链路由场景级 TP 承载，见 skill `test-point-workflow`）；名称段：**逐字取自 TP 清单该 TP 的 `测试点名称`**，不得缩写、改写、同义替换；TP 侧修复导致测试点名称变更时，关联 TC 的名称段同步更新（名称段不一致由机验直接拦截） |
| 用例名称 / 测试数据 / 操作步骤 / 预期结果 | 依下方【TC 四列判据】 |
| 用例类型 | 仅 `正向` / `反向` / `边界` / `场景` / `异常`（**纯白名单，无括注变体**，保证统计不失真） |
| 测试方法 | 单值=该用例采用的主要设计方法，六枚举白名单：`等价类+边界值` / `决策表` / `状态迁移` / `场景法` / `正交实验` / `错误推测`（因果图按决策表口径落值）；来源=方法选型决策指南按需求形态匹配（选型成果随条目落本列，机验白名单见 skill `citation-verify`） |
| 澄清依据 | 无：`-`；有：`C-编号` 或 `C-编号(默认)`；多值 ` ;; ` 分隔；编号必须存在于 clarifications.md |
| 出处锚点 | 引用与该用例最直接相关的原文位置（通常继承关联 TP 的锚点，也可按需补充）；按 skill `citation-verify` 锚点口径 |

**分隔符口径**：编号与名称的展示分隔用**空格**（关联业务功能、关联TP）；多值项（锚点、澄清依据、用例展开重点）仍用 ` ;; `；**`<br>` 仅限操作步骤列**（步骤间换行），锚点/澄清依据/测试数据等其他列禁用。

**取消优先级字段**：TP、TC 均不设优先级列。排序即优先级——清单顺序 = 业务功能（关口 1 选定序）簇 → 簇内测试点按知识④§六步骤 6 → 测试用例承接其主 TP 所在顺序、簇内同法则排列（纯人工判据，不加机验）。

### TC 四列判据（标题 / 测试数据 / 操作步骤 / 预期结果）

> 方法论（取什么值、按什么方法铺场景）不在本节复述：取值依知识③§1.2与知识①§5.1.1/§5.1.2，见方法选型节。

**内容可追溯性三层口径**：四列是设计推导产物，不要求逐字出自资料，但出处分层——

| 内容类型 | 出处要求 |
|---|---|
| **判定性内容**（数值/阈值/枚举值/状态名/角色名） | 必须可由关联 TP 锚点或澄清答复**推导还原**（锚点写上限 25 → 测 26 是合法推导；锚点无 25 而写 25 即臆造） |
| **提示文案** | 资料给了文案→照抄锚点原文；没给→写语义级预期（如「提示工作空间 ID 必填」），禁杜撰具体文案 |
| **编排性内容**（步骤顺序/前置账号与环境/构造方法） | 测试设计自由度，不受资料逐字约束；涉及的状态名/角色名/字段名须与资料术语一致 |

**术语落名禁泛化**：资料已明确的角色名/状态名/字段名/文案，用例中必须照抄 PRD 叫法（如「测试管理人/负责人」不得写成「有权限的用户」）；资料未给才允许语义级预期表述。前置条件/测试数据/操作步骤/预期结果四列一体适用。

**标题**
- 结构 = **「验证 + 场景 + 预期落点」单式**：一律以「验证」开头（与 TP 名称风格统一），预期承载在句中或句尾（如「验证金额超单笔限额时交易拒绝并提示」「验证编辑风险上传空文件被拦截」）。
- **一次判定原则**：一个标题只承载一次判定。预期结果可含多个观察点（如「余额不变 + 流水生成」），但须同属一次判定；承载第二种判定即拆分为两条用例。
- **短语级 ≤30 字**（与 TP 名称对称）。
- **对象词沿用主 TP 名称中的 PRD 叫法**，不自创同义词——F→TP→TC 名称链检索键一致。
- **同 TP 直属用例标题以差异点区分**（状态/数据语义/场景分支）；仅以序号或「验证 1 / 验证 2」式区分判硬凑（归质检维度 4）。
- **标题禁承载具体数据字面值**（如「51 个字符」「WS001」，写测试数据列）；场景语义词（上边界/超长/空值/缺省）允许。

**测试数据**
- 两种承载形态（可并存，以「；」分隔）：
  - **赋值式**：`字段=值`，多值以「；」分隔；日期区间写「起 至 止」；构造方法括注「（构造：…）」；多记录须逐条枚举或给出生成规则（如「编号分别为 X 和 Y」），禁「多条数据」式含糊。
  - **状态描述式**：场景背景/数据就绪态按自然语句书写（含具体数值，如「需求 R1 已关联 [D001]」），不因自然语句含冒号判错。
- **同一承载形态内符号一致**：赋值式内禁「：」「=」「，」混排作分隔符。
- 给**具体值**或可执行构造方法，金额/字段给到具体数值；禁止「系统正常」「适当数据」类可随意替代的表述。
- 值的选择按知识③§1.2 四要素/六场景、知识①等价类与边界点执行。

**操作步骤**
- **动词开头、编号分步**（「1.」与「1、」均可），**步骤间以 `<br>` 分隔**（md 单元格内换行：展示层直接多行、导出 xlsx 转 `\n`）；不含歧义词（「等一下」「适当输入」类禁用）。
- **业务等待例外**：等待对象为系统行为（定时任务触发、状态扭转、异步回调、消息到达）且后续步骤含该行为的可判定观察点时，写「等待/触发」合规；等待对象为执行者判断或无法判定的等待（「等一会」「稍候再看」）仍违规。
- **准备类步骤归属判据**：准备产物被后续步骤引用或观察（如「在源平台创建记录并记录编号」供后续核对）→ 允许作为前置编号步骤；纯环境置备、无中间观察（如「服务置为不可用」）→ 写前置条件列，不进步骤。

**预期结果**
- 具体到**可观察物**：数据值/一致性（值类判定）、界面元素状态（高亮/灰显/置灰）、提示文案、状态变更、消息推送内容五类承载形态任一；可直接判 pass/fail。
- **一致性判定必须点名对比基准**（源系统/前端展示/数据库/导出文件/源平台），禁「数据准确无误」式无基准断言。
- 错误提示指向**具体字段与原因**，不用通用模糊提示（知识③§1.2 判定规则）。

### 送检门槛

`failures` = 0 才送检（机验命令与逐列自校见 skill `citation-verify`"生成端送检前"及"送检前自校"节）；重试与异常处置（exit 2 / 三振上限）按测试专家机验规则。`warnings`（TP 覆盖缺口）逐条人工确认，无 TC 关联的 TP 必须有书面理由记入 state.md。

## 乙 · 质检维度（阶段 6，QA 全量检；大清单按功能分批连续检完）

| # | 维度 | 判定要点 | 分级参考 |
|---|---|---|---|
| 1 | TP 覆盖完整性 | 每个 TP ≥2 条用例且正/反/边界分布合理；缺反向或边界 → 问题；**字段校验类 TP 抽查展开矩阵完整性**（字段×约束、空值逐字段遍历）；**边界配对完整**（达界+越界）；**经验场景清单命中形态零覆盖**（注入/特殊字符/分页排序/复制独立性等） | 缺失→阻塞；偏少→重大；矩阵/配对/清单缺项→一般（多发或核心场景升重大） |
| 2 | 方法适配 | TP 需求形态 ↔ `测试方法` 匹配（如状态流转类 TP 的直属 TC 全非状态迁移、多条件组合类全无决策表 → 提示）；纯人工判据 | 错配→一般 |
| 3 | 语义一致 | TC 确实在验证其关联 TP，不是跑题用例；**判定性内容（数值/枚举/文案/状态名）须可由关联 TP 锚点或澄清答复推导，推导不出判臆造** | 跑题→阻塞；臆造→阻塞 |
| 4 | 硬凑检测 | 同值改名、伪边界、把两条用例拆成四条凑数 | 重大 |
| 5 | 字段质量 | 按甲节【TC 四列判据】逐列核查（含一次判定原则、歧义等待例外、测试数据两形态、`<br>` 换行、一致性对比基准）；**术语落名：资料已明确的角色/状态/字段/文案泛化表述判错** | 重大 |
| 6 | 用例重复 | 两条 TC 实质相同（同 TP+同数据+同步骤+同预期） | 重大 |
| 7 | 锚点抽验 | 每功能模块 ≥3 条：md 直读；docx/xlsx 用 inspect_anchor.py | 不实→阻塞 |
| 8 | 排序 | 用例承接其主 TP 所在顺序、簇内同法则（纯人工判据，不加机验） | 一般 |
| 9 | 澄清/默认 | 澄清编号真实、语义一致；`(默认)` 条目重点核 | 误用→阻塞；风险→重大 |

## 纪律

QA 只检不修、每问题必附证据锚点；测试专家禁止自检替代质检专家检；模板列名是机器契约，增删列必须先改 skill `citation-verify` 的机验脚本再改本模板。格式问题（锚点格式/表头列名/摘抄长度/横线）由测试专家机验前置拦下，**不进质检范围**。
