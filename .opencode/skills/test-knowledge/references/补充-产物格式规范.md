# 补充件：产物格式规范

> **身份**：本文件是补充件，不是四份原文之一。定位：机验脚本（`citation-verify/scripts/verify_citation.py` / `inspect_anchor.py`）要求的**硬格式白名单**，供测试专家（test-expert）写产物前消费、机验自校。
> **语义判据不在此重写**：命名/颗粒度/切分见原文④《测试点生成指南》与补充《TP切分与命名判别》；TC 三列判据见补充《TC列判据》；排序见原文④§六步骤 6 与补充件裁决三/六。本文只载"表面事实"，知识变更不牵连本文。
> **检查分工**：格式问题由测试专家机验前置拦下，**不进质检专家（qa-expert）检查范围**。

## 一、引用锚点（TP / TC / clarifications / resources-index 通用）

1. 唯一口径：`文件名:行号 => "摘抄"`；多锚点用 ` ;; ` 分隔。
2. 摘抄 ≤50 字；必须是定位行的**连续原文片段**（可去表格竖线压缩）；禁止改写、缩合、空格补齐。
3. 摘抄与锚点**不得包含**表格竖线 `|`（会把列拆断，机验判格式非法）。
4. 禁止裸格式 `文件名:行号`（无摘抄段）。
5. 横线/分隔符一律 ASCII 短横线 `-`；长横线 `—` 会被机验拒收（澄清依据列尤其注意）。
6. **写一条、当场验一条**：先跑 `inspect_anchor.py --help` 确认用法，写一条锚点就按该用法跑一次机验；攒批后补验视为违规。
7. 数值型具体值（字数/长度/个数/金额）落笔前逐字自校一遍（防"自称 25 字实为 17 字"类自相矛盾）。

## 二、TP 表（6 列，列名与机验 `TP_REQUIRED` 逐字一致）

```
编号 | 关联业务功能 | 测试点名称 | 类型 | 澄清依据 | 出处锚点
```

| 字段 | 取值规则 |
|---|---|
| 编号 | `TP-001` 三位数字起步；重排后**必须重编号**（连续无跳号） |
| 关联业务功能 | 关口 1 用户选定的业务功能：F 编号 + PRD 原文名称（如 `F01 · 需求创建`）；禁自创模块词；场景级条目带"（局部场景）"标注 |
| 测试点名称 | 判据见原文④§三 + 补充《TP切分与命名判别》词面筛检（不重抄） |
| 类型 | 仅 `功能级` / `场景级` |
| 澄清依据 | 无：`-`；有：`C-编号` 或 `C-编号(默认)`；多值 ` ;; ` 分隔；编号必须存在于 clarifications.md |
| 出处锚点 | 本件 §一 格式，至少 1 条，一般 1~3 条 |

## 三、TC 表（11 列，列名与机验 `TC_REQUIRED` 逐字一致）

```
编号 | 关联业务功能 | 关联TP | 用例名称 | 用例类型 | 前置条件 | 测试数据 | 操作步骤 | 预期结果 | 澄清依据 | 出处锚点
```

| 字段 | 取值规则 |
|---|---|
| 编号 | `TC-001` 三位数字起步 |
| 关联业务功能 | 同 TP 取值（主 TP 所属业务功能） |
| 关联TP | 恰好一个，格式 `TP-xxx`，必须存在于一 TP 清单（一 TC = 一 TP 裁决，见补充《TP切分与命名判别》） |
| 用例名称 / 测试数据 / 操作步骤 / 预期结果 | 判据见补充《TC列判据》（不重抄） |
| 用例类型 | 仅 `正向` / `反向` / `边界` / `场景` / `异常`（**纯白名单，无括注变体**，保证统计不失真） |
| 澄清依据 / 出处锚点 | 同 §一 / §二 |

**取消优先级字段**：TP、TC 均不设优先级列。排序即优先级——清单顺序 = 业务功能（关口 1 选定序）簇 → 簇内测试点按原文④§六步骤 6（正向 → 核心逻辑与状态 → 异常处理 → 边界值与数据校验 → 其他）→ 测试用例承接其主 TP 所在顺序、簇内同法则排列（裁决六 B2）。

## 四、clarifications 表（7 列，列名与机验 `CLAR_REQUIRED` 逐字一致）

```
编号 | 来源 | 问题 | 影响面 | 默认建议 | 答复 | 状态
```

| 字段 | 取值规则 |
|---|---|
| 编号 | `C-01` 起递增 |
| 来源 | QA 报告编号（如 `qa-materials.md R1 · Q-M-R1-C1`）或关口答复 |
| 影响面 | 写涉及条目的**当前**编号；条目重编号后**同步更新**（防指针漂移） |
| 默认建议 | 具体可执行、可直接转成断言口径；不可执行的不算默认建议 |
| 答复 | 可留空盛放原文答复 |
| 状态 | 仅 `待答复` / `默认生效` / `已答复` |

## 五、送检前自校（一次跑完，零才送检）

1. `verify_citation.py` 一次跑完 `--tp`/`--tc`/`--clar`，`failures` 与 `fatal_messages` 全零才送检；具体参数以脚本 `--help` 为准（不依赖本文或 AGENTS 中的示例命令，防脚本演进后双维护过期）。
2. 逐列对照本件 §二/§三/§四 的白名单：类型/用例类型/澄清依据/锚点格式。
3. 表头列名与脚本 `*_REQUIRED` 逐字核对（改列名必须同步改脚本，且双向核对）。
4. 每条锚点已当场跑过 `inspect_anchor.py`（§一第 6 条）。
