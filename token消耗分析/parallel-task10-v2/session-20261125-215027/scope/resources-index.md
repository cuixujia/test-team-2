- 锚点：业务需求说明书.md:17-20 => "所有经平台受理的需求及其处理记录自动存档，形成可追溯的需求台账"

### 3.1 本期包含范围（需求统一受理、需求评审、基础需求存档）
- 锚点：业务需求说明书.md:26-36 => "各业务部门通过平台统一入口提交系统建设需求，科技/IT部门集中接收"
- 概要：需求统一受理含创建、信息登记（标题、描述、业务领域分类）与按领域归类；需求评审通过 BRD 协作会话组织，评审通过后上传最新 BRD 进入待派发；基础需求存档为自动存档台账。

### 4.2 环节一：需求提出（业务部门）
- 锚点：业务需求说明书.md:58-63 => "业务部门通过平台统一入口创建系统建设需求，填写需求标题、描述、所属业务领域等基本信息"
- 概要：参与角色为业务部门用户（需求发起人）；填写标题、描述、所属业务领域；触发条件为有系统建设需求；完成标志为创建成功、进入待沟通、生成需求 ID 与 BRD 协作会话。

### 4.2 环节二：统一受理归口（科技/IT部门）
- 锚点：业务需求说明书.md:65-73 => "可修改需求标题、维护需求信息"
- 概要：参与角色为科技/IT 产品管理人员（受理人/派发人）；集中接收、统一登记分类、业务领域归类、可改标题与维护信息；前置为需求已创建并待沟通；完成标志为进入待评审。

### 4.2 环节三：需求评审
- 锚点：业务需求说明书.md:75-83 => "BRD 文档评审通过并上传最新版本，需求进入「处理中」状态"
- 概要：参与角色为评审组织者与相关技术负责人；通过 BRD 协作会话评审、补充细节、明确边界；评审通过后上传最新 BRD 版本；前置为待评审，完成标志为进入处理中。

### 4.3 需求状态流转
- 锚点：业务需求说明书.md:116-130 => "BRD 评审通过并上传最新版本"
- 概要：需求链路为待沟通→待评审→处理中→已完成/已取消；同时列任务与功能点迁移：待承接→处理中/已拒绝/已撤回，处理中→待拆解、待拆解→已拆解、全部已拆解→任务完成，处理中→已完成/业务已拒绝。
