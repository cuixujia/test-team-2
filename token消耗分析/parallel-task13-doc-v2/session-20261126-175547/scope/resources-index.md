### 4.1 主流程总览

### 环节一：需求提出（业务部门）
- 锚点：业务需求说明书.docx:P55#环节一：需求提出（业务部门） => "业务部门通过平台统一入口创建系统建设需求，填写需求标题、描述、所属业务领域等基本信息"

### 环节二：统一受理归口（科技/IT部门）
- 锚点：业务需求说明书.docx:P61#环节二：统一受理归口（科技/IT部门） => "集中接收各业务部门提交的系统建设需求，统一登记和分类。"
- 概要：参与角色为科技/IT 产品管理人员（受理人/派发人）；集中接收、统一登记分类、业务领域归类、可修改标题与维护需求信息；前置为需求已创建并处于待沟通；完成标志为进入待评审。

### 4.3 需求状态流转
- 锚点：业务需求说明书.docx:P105#4.3 需求状态流转 => "科技/IT完成受理登记和分类"
- 概要：BRD 状态表：待沟通→待评审（科技/IT 完成受理登记和分类）、待评审→处理中（BRD 评审通过并上传最新版本）、处理中→已完成或已取消；另含任务与功能点流转行。
