# 测试用例生成与清单规范

## 生成规则

### 生成红线

违反即虚构，QA 判阻塞：

1. 用例涉及的字段、状态、角色、文案须有原文锚点，资料没有的不生成用例。
2. 不补造业务规则与提示文案，不把未描述内容写成已描述。
3. 已登记澄清的对象，测试数据与预期按台账答复生成，未答复按默认建议；未登记且原文无支撑的内容只写宽泛表述，预期写语义级，不得整块跳过不生成。

### 展开数量守恒

TC 条数按主 TP 形态的客观分支计数核算，`用例展开重点` 只提示方向、不限定条数，机验每 TP 直属 2 条的下限不是展开目标。

| TP 形态 | 计数核算规则 | 示例 |
|---|---|---|
| 字段校验 / 接口参数校验 | 字段数 × 约束类型数，含原文已给与发散约束；空值逐字段各一条、每条只留空一个必填字段，另加全字段空值 1 条 | 6 个任务字段，必填、长度、SSO 有效性 → 11 条 |
| 状态流转 | 合法边逐条 + 非法扭转 ≥1 | 7 条合法边 → ≥8 条 |
| 查询/筛选 | 查询项逐项 + 组合筛选 1 + 空结果 1 | 状态、领域、时间 → ≥5 条 |
| 权限控制 | 角色 × 操作矩阵的有效格逐格 + 越权反向 ≥1 | 承接人、派发人 × 承接、撤回 → ≥5 条 |
| 场景级主流程 | 基本流 1 + 各备选流逐条 | 3 个备选流 → ≥4 条 |
| 可靠性与稳定性容错 | 外部依赖逐项 + 开关分支逐项 | 5 个外部系统 → ≥5 条 |
| 数据一致性 / 数据正确性 | 各对比基准、一致性方向逐项 | 订单、库存、流水三方 → ≥3 条 |
| 表外形态 | 按原文客观分支逐条计，每分支 ≥1 条 | — |

- 发散约束展开的用例落 `补充条目`。
- 边界值逐点落到具体取值，精度类对称处理。
- 经验场景按需求形态命中才展开，不机械全覆盖。
- 条数来自客观计数：禁止为凑数复制改名、伪边界、同值换装，禁止仅以序号或「验证 1 / 验证 2」式区分标题，禁止空壳充数。

### 排序规则

- 主 TP 排在哪，它的用例就排在哪；同一业务功能、同一条 TP 的用例各自排在一起，中间不插别的 TP。
- 不许按用例类型或测试方法把整张表重新排序；场景级 TP 的用例也不集中挪到清单最后。
- 一条 TP 内部的用例按 正向 → 反向/异常 → 边界 排。排序由 QA 判定，生成方不回读重排。

## 用例四列

字段名、状态名、角色名照抄原文术语；提示文案原文有则照抄、无则写语义级预期；步骤与环境属测试设计自由度，但术语须与资料一致。

| 列 | 要求 |
|---|---|
| 标题 | 「验证 + 场景 + 预期落点」，一次判定，≤30 字；同 TP 内以差异点区分，不重名；具体值写 `测试数据` |
| 测试数据 | `字段=值` 或状态描述式；多值「；」分隔，日期「起 至 止」，构造标「构造：…」；须给具体值或构造方法，禁「适当数据」类表述 |
| 测试步骤 | 数组，动词开头、编号分步，每项一个步骤；禁歧义词；等待系统行为且后续有可判定观察点时允许「等待/触发」；环境置备写 `前置条件` |
| 预期结果 | 可观察、可判 pass/fail：数据值、界面元素、提示文案、状态变更、消息内容；一致性须点名对比基准；错误提示指向具体字段与原因 |

## 清单结构

一个业务功能一个文件，按清单编号命名 `tc-{功能号}.json`，UTF-8 JSON。文件骨架：

```json
{
  "name": "F01-TC",
  "headers": ["AI用例编号", "系统", "系统功能", "测试点", "用例名称", "优先级", "用例类型", "测试方法", "前置条件", "测试数据", "测试步骤", "预期结果", "依据类型", "备注", "需求分组名称", "需求名称", "是否可入库", "是否删除"],
  "rows": [
    ["TC-001", "客户管理系统", "F01 需求新增", "TP-002 验证正常输入新增功能正确性", "验证全部必填合法输入新增成功", "高", "功能用例", "等价类+边界值", "已登录且有新增入口", "客户名称=张三；证件号=110101199001011234", ["1.进入新增页", "2.填写全部必填项", "3.保存"], "保存成功；列表出现该记录；状态=待审核", "原文依据", ["prd1.md:15 => \"保存成功后状态置为待审核\""], "协同平台", "客户需求管理二期", "是", "否"],
    ["TC-002", "客户管理系统", "F01 需求新增", "TP-002 验证正常输入新增功能正确性", "验证超限客户名称创建被拦截", "中", "功能用例", "等价类+边界值", "已登录且有新增入口", "客户名称=51个字符", ["1.进入新增页", "2.名称填51字符", "3.填写其余必填项", "4.保存"], "拦截并提示名称超长；不落库", "澄清依据(C-01)", ["产品需求说明书.docx:P12#客户名称约束 => \"客户名称长度不超过50个字符\""], "协同平台", "客户需求管理二期", "是", "否"],
    ["TC-003", "客户管理系统", "F01 需求新增", "TP-003 验证新增输入域长度与字符约束", "验证姓名特殊字符与空格输入被拦截", "低", "功能用例", "等价类+边界值", "已登录且有新增入口", "姓名=含特殊字符与首尾空格的值", ["1.进入新增页", "2.姓名填入特殊字符值", "3.填写其余必填项", "4.保存"], "拦截并提示字符不合规；不落库", "补充条目", ["字段约束表.xlsx:字段清单#C3 => \"姓名、年龄\""], "协同平台", "客户需求管理二期", "是", "否"]
  ]
}
```

顶层字段：

| 字段 | 要求 |
|---|---|
| name | `功能号-TC`，如 `F01-TC` |
| headers | 下列数据字段名数组，顺序固定、逐字用表内中文名 |
| rows | 每条 TC 一个数组，与 headers 一一对应，独占一个物理行 |

数据字段：

| 字段 | 要求 |
|---|---|
| AI用例编号 | 各文件独立，自 `TC-001` 起三位递增，文件内永久稳定、不得复用。删除或插入条目不改其他编号，删除留空号；新增取本文件当前最大号加一，不回填空号。机验 `TC-\d+` |
| 系统 | 该业务功能所属系统的中文名称，从需求文档取；同一系统的功能跨文件写法一致 |
| 系统功能 | 逐字等于主 TP 的 `系统功能`；机验直接拦截主从挂错簇 |
| 测试点 | `TP-编号 测试点名`；编号须存在于同功能 TP 文件，名称段逐字照抄主 TP 的 `测试点`；一 TC 一 TP，TP 改名时同步更新 |
| 用例名称 | 同 TP 内以差异点区分，不重名 |
| 优先级 | 仅 `高` / `中` / `低`，单值 |
| 用例类型 | 仅 `流程用例` / `功能用例`，单值 |
| 测试方法 | 单值：`等价类+边界值` / `等价类` / `边界值` / `决策表` / `状态迁移` / `场景法` / `正交实验` / `错误推测`；因果图按决策表落值 |
| 前置条件 | 账号、环境、数据就绪态；纯环境置备写本列，不进测试步骤；术语与资料一致 |
| 测试数据 | 赋值式或状态描述式；给具体值或构造方法 |
| 测试步骤 | 数组，每项一个步骤，动词开头、编号分步 |
| 预期结果 | 可观察、可判 pass/fail |
| 依据类型 | 逐条标注单值，同 TP 下各类用例可并存，不按 TP 打包：`原文依据` = 用例的测试数据与预期在原文有支撑；`澄清依据(C-编号)` = 测试维度原文未明确，依据用户澄清答复确立，C 编号须在澄清台账存在；`补充条目` = 原文无对应描述且未走澄清，按测试方法论与资料理解发散补设的用例； |
| 备注 | 数组，每项一条原文锚点；取与该用例最直接相关的原文位置，通常继承主 TP 锚点，可按需补充 |
| 需求分组名称 | 取需求信息 `需求分组名称` 逐字照抄，全文件数据行同值；空值写 `""`，禁自造 |
| 需求名称 | 取需求信息 `需求名称` 逐字照抄，全文件数据行同值；空值写 `""`，禁自造 |
| 是否可入库 | 枚举 `是` / `否`，本场景默认填 `是`；机验只校验取值在枚举内，用户可逐条改值 |
| 是否删除 | 枚举 `是` / `否`，本场景默认填 `否`；机验只校验取值在枚举内，用户可逐条改值 |
| 通用书写 | 测试步骤与备注为数组（测试步骤每项一个编号步骤）；其余字段为字符串，字符串内禁真实换行；锚点摘抄含双引号时按 JSON 规则转义为 `\"` |
